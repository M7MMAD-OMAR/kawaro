## [0.4.3] - 2026-10-30

### Fixed
- Update page shows what really happens ([S-101](https://github.com/M7MMAD-OMAR/kawaro)): the window now polls while checking so the real download percent shows, the automatic install mode is announced on the page, the daemon stays alive 1.5 s answering "installing" before it exits, and after a restart the page reopens with "Updated to X" or, when the install failed, with a failed banner. | صفحة التحديث تعرض ما يحدث فعلاً: النافذة تستعلم أثناء البحث فتظهر نسبة التنزيل الحقيقية، ويُعلَن عن التثبيت التلقائي في الصفحة، وتبقى الخدمة 1.5 ثانية تجيب "جارٍ التثبيت" قبل الخروج، وبعد إعادة التشغيل تُفتح الصفحة بشريط "تم التحديث" أو بشريط الفشل عند تعذّر التثبيت.
- MSI upgrade really replaces the files ([S-100](https://github.com/M7MMAD-OMAR/kawaro)): upgrading Windows from 0.4.0 or 0.4.2 to a newer MSI, by double click, `msiexec /i` or the in-app update, failed with 1603 and rolled back (StartDaemon error 2753, "DaemonExe is not marked for installation"), and a failed attempt could leave an emptied folder. Windows Installer kept an installed exe it judged user-modified (its modification time is later than its creation time, common with a cabinet built in another time zone); the two exes now carry a File.Version (`scripts/windows/msi-fixup.sh`), which always replaces an unversioned installed file, and every ComponentGuid changes with each build (`scripts/windows/guid-tail.sh`) so the old product is removed first and the new files are written; user data in `%APPDATA%` is untouched. | ترقية MSI تستبدل الملفات فعلاً: كانت الترقية على ويندوز من 0.4.0 أو 0.4.2 إلى حزمة أحدث، بالنقر المزدوج أو `msiexec /i` أو التحديث من داخل التطبيق، تفشل بالخطأ 1603 وتتراجع (الخطأ 2753 في StartDaemon)، وقد تترك مجلداً فارغاً بعد محاولة فاشلة. كان ويندوز يحتفظ بملف تنفيذي مثبت يعدّه معدّلاً من المستخدم (وقت تعديله لاحق لوقت إنشائه)؛ صار للملفين التنفيذيين إصدار ملف (`scripts/windows/msi-fixup.sh`) يستبدل دائماً الملف المثبت غير المؤرَّخ بإصدار، ويتغير معرّف كل مكوّن مع كل بناء (`scripts/windows/guid-tail.sh`) فيُزال المنتج القديم أولاً ثم تُكتب الملفات الجديدة؛ بيانات المستخدم في `%APPDATA%` لا تُمس.
- Alt plus drag on Hyprland ([S-095b](https://github.com/M7MMAD-OMAR/kawaro)): the drop hive now shows whether Alt is pressed before or after the drag starts (a hive hidden by a pointer move with no drag is shown again while the key is held), every wait ends after `hold_max_ms` (default 10000), and each hold that ends without a hive logs `hold: <reason>`. | Alt مع السحب على Hyprland: تظهر الخلية سواء ضُغط Alt قبل بدء السحب أو بعده (الخلية التي أخفتها حركة المؤشر بلا سحب تظهر من جديد ما دام المفتاح مضغوطاً)، وكل انتظار ينتهي بعد `hold_max_ms` (الافتراضي 10000)، وكل ضغطة تنتهي بلا خلية تكتب السطر `hold: <السبب>`.
- Update experience, window and restart ([S-099b](https://github.com/M7MMAD-OMAR/kawaro)): the Updates page shows the installed and the available version, a download percent with its size, clear messages for download finished and installing, and a short "What is new" area (3 to 5 bullets for the installed version from the bundle and for the new version from the signed manifest); after Update now in the settings window the app restarts and reopens settings on the Updates page by itself with "Updated to X", and the tray has an About item that opens the same page. «تجربة التحديث، النافذة وإعادة التشغيل: تعرض صفحة التحديثات النسخة المثبّتة والنسخة المتاحة ونسبة التنزيل مع حجمه ورسائل واضحة لاكتمال التنزيل والتثبيت وقسم «الجديد» القصير (من 3 إلى 5 نقاط للنسخة المثبّتة من الحزمة وللنسخة الجديدة من البيان الموقّع)؛ وبعد «حدّث الآن» في نافذة الإعدادات يعيد التطبيق التشغيل ويفتح الإعدادات على صفحة التحديثات من تلقاء نفسه مع «تم التحديث إلى X»، وفي صينية النظام عنصر «حول كوارو» يفتح الصفحة نفسها».
- Update experience, core and IPC ([S-099a](https://github.com/M7MMAD-OMAR/kawaro)): the update reply carries the real download percent and size, the signed manifest carries optional short "what is new" notes in English and Arabic (3 to 5 lines each, bundled for the installed version in `docs/whats-new/`), and the Windows helper repairs once, or reports a clear message naming the installer, if `kawarod.exe` is missing after an update. «تجربة التحديث، النواة وIPC: يحمل رد التحديث نسبة التنزيل الحقيقية وحجمه، ويحمل البيان الموقّع ملاحظات «الجديد» القصيرة بالإنجليزية والعربية (من 3 إلى 5 أسطر لكل لغة، ومضمّنة للنسخة المثبّتة في `docs/whats-new/`)، ويصلح مساعد ويندوز مرة واحدة أو يعرض رسالة واضحة تسمّي المثبّت إذا غاب `kawarod.exe` بعد التحديث».

## [0.4.2] - 2026-10-29 «إصلاح الترقية»

### Fixed
- MSI upgrade keeps the program files ([S-097](https://github.com/M7MMAD-OMAR/kawaro)): upgrading Windows from an older version with the MSI or the in-app update removed `kawaro.exe` and `kawarod.exe` and left a broken Start shortcut, because the old product was removed before the new files were installed; the installer now removes the old product after `InstallFinalize`, so the shared components keep their files. Users of 0.4.1 on Windows run the 0.4.2 MSI once (or reinstall); a fresh install of 0.4.1 was fine. «ترقية حزمة MSI تحتفظ بملفات البرنامج: كانت الترقية على ويندوز من نسخة أقدم بحزمة MSI أو بالتحديث من داخل التطبيق تحذف `kawaro.exe` و`kawarod.exe` وتترك اختصار قائمة ابدأ معطلاً، لأن المنتج القديم كان يُزال قبل تثبيت الملفات الجديدة؛ صار المثبّت يزيل المنتج القديم بعد `InstallFinalize` فتحتفظ المكونات المشتركة بملفاتها. على مستخدمي 0.4.1 في ويندوز تشغيل حزمة MSI الخاصة بـ 0.4.2 مرة واحدة (أو إعادة التثبيت)؛ والتثبيت الجديد لـ 0.4.1 كان سليماً».

- WinGet per-user scope guard ([S-078](https://github.com/M7MMAD-OMAR/kawaro)): `scripts/release/check-winget-scope.sh` reads the `ALLUSERS` and `MSIINSTALLPERUSER` properties of the built MSI and refuses a manifest that declares `Scope: user` when the installer is not per-user by construction, because winget reads the program entry under the user's own hive while an elevated install without those properties registers it under the machine hive, where winget does not look; the measured cause is that `wixl` accepts `InstallScope="perUser"` and drops it, so the next MSI build writes the two properties explicitly, and `tests/release/s078_winget_scope.sh` builds real MSIs with wixl in both shapes and covers the non-user scopes as well. «حارس نطاق WinGet لكل مستخدم: يقرأ `scripts/release/check-winget-scope.sh` خاصيتي `ALLUSERS` و`MSIINSTALLPERUSER` من حزمة MSI المبنية ويرفض ملف تعريف يعلن `Scope: user` حين لا يكون المثبّت لكل مستخدم secara أصيل، لأن winget يقرأ مدخل البرنامج من خلية المستخدم نفسه بينما يسجّل التثبيت المرفوع بلا هاتين الخاصيتين في خلية الجهاز، حيث لا يبحث winget؛ والسبب المقيس أن `wixl` يقبل `InstallScope="perUser"` ويهملها، ولذلك تكتب الحزمة التالية هاتين الخاصيتين صراحةً، ويبني `tests/release/s078_winget_scope.sh` حزم MSI حقيقية بـ wixl في الصيغتين ويغطي النطاقات غير الخاصة بالمستخدم أيضاً».


- WinGet version consistency guard ([S-078](https://github.com/M7MMAD-OMAR/kawaro)): `scripts/release/check-winget-versions.sh` reads the DisplayVersion the MSI writes to the registry and checks every manifest of the package against it, refusing a set where some manifests declare `AppsAndFeaturesEntries.DisplayVersion` and others do not; the mixed set is the failure the Microsoft community repository cannot map to an available version, and it is invisible until the next release is rejected, so `tests/release/s078_winget_versions.sh` builds a real MSI with wixl and covers both shapes and the mixed one, and the check runs in the release suite. «حارس اتساق إصدارات WinGet: يقرأ `scripts/release/check-winget-versions.sh` نسخة DisplayVersion التي تكتبها حزمة MSI في السجل ويقارنها بكل ملف تعريف في الحزمة، ويرفض المجموعة التي تعلن `AppsAndFeaturesEntries.DisplayVersion` في بعضها دون بعض؛ وهذه المجموعة المختلطة هي الخلل الذي يعجز مستودع مايكروسوفت عن ربط النسخة المثبتة بإصدار متاح، ولا يظهر إلا حين يُرفض الإصدار التالي، ولذلك يبني `tests/release/s078_winget_versions.sh` حزمة MSI حقيقية بـ wixl ويغطي الصيغتين والمجموعة المختلطة، والفحص يعمل ضمن مجموعة اختبارات الإصدار».

- WinGet package submission ([S-078](https://github.com/M7MMAD-OMAR/kawaro)): the 0.4.0 manifests are open for review at [microsoft/winget-pkgs#462805](https://github.com/microsoft/winget-pkgs/pull/462805) with the version, installer, English locale and Arabic locale files, the published MSI URL and SHA-256, the per-user scope and the real product code; all twelve automated checks pass, `winget validate --manifest` exits 0, and `winget install --manifest` completes silently on Windows 11 and reports `kawaro 0.4.0`; the package identifier is `Sbarah.Kawaro`, the merge still waits for one approving review from a Microsoft moderator, and the MSI keeps its self-signed test certificate, so nothing here claims a trusted publisher signature. «رزمة WinGet: ملفات النسخة 0.4.0 مفتوحة للمراجعة في [microsoft/winget-pkgs#462805](https://github.com/microsoft/winget-pkgs/pull/462805) بملفات النسخة والمثبّت وملفَّي اللغة الإنجليزية والعربية، ورابط حزمة MSI المنشورة وبصمتها، والنطاق لكل مستخدم ومعرّف المنتج الحقيقي؛ تجتاز الفحوص الآلية الاثنتي عشرة كلها، ويخرج `winget validate --manifest` بالرمز 0، و`winget install --manifest` ينتهي بصمت على ويندوز 11 ويبلّغ `kawaro 0.4.0`؛ ومعرّف الحزمة `Sbarah.Kawaro`، ولا يزال الدمج ينتظر موافقةَ مشرف من مايكروسوفت واحدة، وتحتفظ حزمة MSI بشهادة الاختبار ذاتية التوقيع، فلا شيء هنا يدّعي توقيع ناشر موثوق».
