# Changelog

All notable changes. Format: one line per finished story, newest first under each version.

## [Unreleased]

### Added
- Drop from Explorer onto a hive cell on Windows (S-047): during a file drag over the drop hive the cursor is polled every 16 ms to highlight the cell under it, a drop on a cell runs that action like a click and leaves the original in place, a drop elsewhere closes the hive, and the shortcut shows the drop hive only while the left button is held (built and unit tested on Linux, not yet verified on a live Windows system; S-052). «الإفلات من المستكشف على خلية في ويندوز: أثناء سحب ملف فوق الخلية يُقرأ موضع المؤشر كل 16 مللي ثانية لتمييز الخلية تحته، والإفلات على خلية يشغّل إجراءها كالنقر ويبقى الأصل في مكانه، والإفلات خارج الخلايا يغلقها، ولا يفتح الاختصار خلية الإفلات إلا والزر الأيسر مضغوط».
- Update command (S-054c): `kawaro update` checks, downloads, verifies and installs from the terminal, with stable exit codes. «أمر التحديث: يفحص وينزّل ويتحقق ويثبّت من الطرفية برموز خروج ثابتة».
- macOS base (S-069, ADR 0009): a `macOS` workflow builds and tests the workspace on a GitHub Apple silicon runner (story branches, on demand and weekly; informational, it never blocks main); the first run shows that only `crates/ui` fails to compile there, and `docs/macos-gap.md` lists the gaps and the next stories. أساس macOS (S-069، ADR 0009): سير عمل `macOS` يبني المشروع ويختبره على جهاز Apple silicon في GitHub (على فروع القصص وعند الطلب وأسبوعياً، للعلم فقط ولا يمنع الدمج)، وأظهر أول تشغيل أن `crates/ui` وحدها لا تُترجم هناك، ويسرد `docs/macos-gap.md` الفجوات والقصص التالية.
- English hero film (S-070): the English home page plays an English cut of the product film, mirrored for left to right, with its own poster and the same silent, looping, reduced motion behaviour. فيديو الواجهة الإنجليزي (S-070): تعرض الصفحة الرئيسية الإنجليزية نسخة إنجليزية من فيديو المنتج، معكوسة للاتجاه من اليسار إلى اليمين، مع صورة مؤقتة خاصة بها وبالسلوك نفسه: صامت ومتكرر ويحترم تقليل الحركة.
- Hero film (S-068): the Arabic home page shows the product film (22 seconds, silent, looping, about 1 MB, with a poster and reduced motion respected) instead of the CSS demo window, rebuilt with the Kawaro name and beehive mark; the site now allows same origin media and muted autoplay. فيديو الواجهة (S-068): تعرض الصفحة الرئيسية العربية فيديو المنتج (22 ثانية، صامت ومتكرر، نحو ميغابايت واحد، مع صورة مؤقتة واحترام لتقليل الحركة) بدل نافذة العرض البرمجية، وقد أُعيد بناؤه باسم كوارو وشعار الكوّارة، ويسمح الموقع الآن بوسائط من الأصل نفسه وبتشغيل تلقائي صامت.
- Rename to Kawaro / كوارو (S-066): the product, binaries (`kawaro`, `kawarod`), crates, packages, app ID, config paths, environment variables, repository and website (`kawaro.sbarah.com`) take the new name, taken from «كوّارة», an old Arabic word for a beehive; new mark, a domed beehive in a hexagon. إعادة التسمية إلى كوارو (S-066): يتغيّر اسم المنتج والملفات التنفيذية والحزم ومعرّف التطبيق والمستودع والموقع، والاسم مأخوذ من «كوّارة» وهي كلمة عربية قديمة لخلية النحل، مع شعار جديد: كوّارة مقبّبة داخل سداسي.

CI adds `windows-cross` (the same scripts on Ubuntu with mingw-w64) and `windows-native` (the tests on Windows with FFmpeg), `make-iso.sh` packs the build and the test programs into an ISO for the test machine, and `run-tests.cmd` runs them there. «أمر واحد يبني كوارو لويندوز على لينكس بذاكرة محدودة ويرفض أي مكتبة mingw تحتاج إلى شحن، وCI يفحصه على ويندوز حقيقي، وصورة قرص تنقل الاختبارات إلى آلة ويندوز».
- Windows engines (S-043): LibreOffice and Ghostscript start suspended with no console window inside a kill-on-close job object, are put in the job and only then resumed, so cancelling, the timeout or the end of a run kills every process they started with `TerminateJobObject`, and the service dying closes the job and kills them too; on Windows a program counts as found only with an `.exe` or `.com` name, and LibreOffice, Ghostscript and FFmpeg are looked up in `PATH`, then their usual install folders, then the registry, never downloaded; a missing engine's error names it with its download page, the LibreOffice profile URL keeps the drive letter, and ffmpeg and ffprobe open no console window (built and unit tested on Linux, not yet verified on a live Windows system; S-052). «على ويندوز يجد كوارو LibreOffice وGhostscript وFFmpeg في أماكنها المعتادة دون إعداد، ويقتل الإلغاء كل ما شغّله المحرك، وتذكر رسالة المحرك الغائب اسمه ورابط تنزيله».
- Windows service start from the CLI (S-042): `kawaro open` starts `kawarod.exe` from the program folder with no console, in its own process group and outside the terminal's job (retried inside the job when breaking away is refused), so closing the terminal is meant to leave the service running (not verified live until S-052, and the Windows service builds from S-045); before `Open` and `Drop` the client lets the service take the foreground with `AllowSetForegroundWindow`, and `kawaro daemon` runs the service and exits with its code; the CLI now builds for Windows. «على ويندوز يشغّل سطر الأوامر الخدمة لتبقى بعد إغلاق الطرفية (يُتحقق منه حياً في S-052)، ويسمح لها بالظهور في المقدمة قبل عرض الخلية».
- Windows folders and output naming without replacing (S-041): settings and user actions live in `%APPDATA%\Kawaro` and the service log folder will be `%LOCALAPPDATA%\Kawaro\logs` (written from S-045), falling back to `SHGetKnownFolderPath` when the variable is missing, one `Config::actions_dir()` replaces the two copies of the actions folder in the daemon and the CLI, and where hard links are unavailable (FAT, exFAT) the output is placed with `MoveFileExW` without replacing, so a file of the same name is never overwritten. «على ويندوز تُحفظ الإعدادات والإجراءات في مجلد التطبيقات المعتاد، ولا يستبدل الناتج ملفاً موجوداً حتى على قرص USB».
- IPC behind one transport (S-040): the client and the service reach each other only through `kawaro_core::transport` (an endpoint, a listener that answers `AlreadyRunning` when a service already answers `ping`, and a stream whose read past its timeout fails with `TimedOut`), still the same socket and protocol on Linux, and on Windows a named pipe per user and session: an access list for the current user alone, no remote clients, one service through `FILE_FLAG_FIRST_PIPE_INSTANCE`, a client that refuses a pipe served by another user, and read timeouts cancelled with `CancelIoEx` (built and unit tested on Linux, not yet verified on a live Windows system; S-052). «العميل والخدمة يتصلان عبر واجهة نقل واحدة: مقبس لينكس كما هو، وعلى ويندوز أنبوب لا يفتحه إلا مستخدمك ولا يقبل اتصالاً من جهاز آخر».

### Changed
- Code cleanup from the review (S-029): one UTF-16 helper and one lock helper per crate, std `OwnedHandle` for the Windows job handles, an atomic one-shot flag for the read deadline, one helper for a missing engine program, the portal switch kept in the settings form, `Abortable` for stopping the portal client, and one sourced scope script for the Windows build scripts; no behaviour change. «تنظيف الشيفرة بعد المراجعة: نسخة واحدة من كل أداة مساعدة، دون أي تغيير في السلوك».

### Fixed
- Site audit (S-071): the 404 page has a body again (it was empty), the Markdown links on the docs pages point at the right file, the English download page no longer overflows at 768 px, the docs edit links reach the 56 px target on phones, and compiled Python files are no longer tracked. تدقيق الموقع (S-071): صفحة 404 فيها محتوى من جديد (كانت فارغة)، وروابط Markdown في صفحات التوثيق تشير إلى الملف الصحيح، وصفحة التنزيل الإنجليزية لا تفيض عند 768 بكسل، وروابط التحرير في التوثيق تبلغ هدف 56 بكسل على الهاتف، ولم تعد ملفات بايثون المترجمة متتبَّعة.
- Engine process trees (S-030): FFmpeg runs in the same kill-on-close job as LibreOffice and Ghostscript on Windows, so it stops when the service dies, and cancelling a video conversion kills every helper process FFmpeg started. «يعمل FFmpeg داخل شجرة عمليات واحدة: يتوقف مع توقف الخدمة في ويندوز، ويوقف الإلغاء كل عملية بدأها».
- Review fixes (S-028): a document on a Windows network share opens in LibreOffice through a `file://server/share/...` URL, a failing accept pauses 50 ms instead of spinning, a Windows client is served even when the next pipe instance cannot be made, a pipe read that brings data at its deadline keeps it, FFmpeg is looked up once per process, the Unix transport removes its own socket, and the Windows build scripts default to `${XDG_CACHE_HOME:-$HOME/.cache}/kawaro-win-target` with their README in separate English and Arabic files. «إصلاحات المراجعة: تفتح ملفات مجلدات الشبكة في ويندوز، ولا تستهلك الخدمة المعالج عند خطأ الاتصال، ولا تضيع بيانات وصلت عند انتهاء المهلة، ولا مسار شخصياً في السكربتات».
- Hyprland release binds in the docs are non consuming (`bindrni`, `non_consuming = true`): a consuming release bind that ignores modifiers makes Hyprland swallow the bare key's press, so the documented `bindri = SUPER, Z` ate every Z typed anywhere and the `ALT_L` one every Alt; `tests/drop/hold_docs.sh` now fails on any consuming release bind in the docs. «ربط الترك الموثَّق في Hyprland صار غير مستهلِك، فلم يعد يبتلع كل حرف Z وكل ضغطة Alt».
