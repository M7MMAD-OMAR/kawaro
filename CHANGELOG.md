- Update rules (S-053a): versions, the signed manifest, channels and the check schedule are decided in code (new `update_check`, `update_channel` and `update_mode` keys in `config.toml`); nothing is downloaded yet. «قواعد التحديث: الإصدارات والبيان الموقّع والقنوات وجدول الفحص، دون تنزيل بعد».

- Windows beta checklist (S-052): `docs/windows-beta-checklist.md` with 14 PASS or FAIL steps for a real Windows machine, `scripts/windows/beta-smoke.cmd` and `collect-logs.cmd` writing results to `%USERPROFILE%\sbarhive-beta-test`, and a Windows beta section in both READMEs; the drop hive, tray icon, shortcut and notifications are listed as not in this build. «قائمة فحص لنسخة ويندوز التجريبية مع سكربتين للنتائج والسجلات وقسم في ملفي README، وما لم يُبنَ بعد مذكور صراحة».
- Windows beta packages (S-051): `scripts/windows/make-zip.sh` writes a reproducible portable zip with `SHA256SUMS` and `scripts/windows/make-msi.sh` a per-user MSI (no administrator rights, upgrade friendly, Explorer menu keys, start at logon, Start menu shortcut); both unsigned, so SmartScreen asks "More info" then "Run anyway" (built on Linux, not yet verified on a live Windows system; S-052). «حزمتان تجريبيتان لويندوز: ملف مضغوط محمول قابل لإعادة الإنتاج وحزمة MSI للمستخدم الحالي دون صلاحيات المدير، وكلتاهما غير موقّعة».
- Explorer right click menu (S-050): `sbarhive integration install` adds SbarHive to the Explorer menu of files with no administrator rights (a verb in `HKCU` that opens the hive for one or many files, plus the notification name and icon), `uninstall` removes exactly those two key trees, and `--dry-run` prints the `reg.exe` commands; on Windows 11 the item is under "Show more options" (built and unit tested on Linux, not yet verified on a live Windows system; S-052). «أمر واحد يضيف صبار هايف إلى قائمة الزر الأيمن في المستكشف دون صلاحيات المدير وأمر يزيله، وعلى ويندوز 11 يظهر البند تحت «إظهار خيارات إضافية»».
- The hive window on Windows (S-046): the hive appears at the pointer inside the work area of its monitor (its shape adapts to the screen edges), undecorated and always on top with no taskbar button, no system shadow and square corners, and takes keyboard focus with `SetForegroundWindow` (a refusal is logged as `sbarhived: foreground refused`); `sbarhived open <files>` sends one request to a running service, or becomes the service, and files that Explorer sends one process at a time within 300 ms share one hive (built and unit tested on Linux, not yet verified on a live Windows system; S-052). «تظهر الخلية على ويندوز عند المؤشر داخل حدود الشاشة وتأخذ التركيز، ويضمّ الأمر open الملفات المرسلة تباعاً في خلية واحدة».
- Windows daemon build (S-045): the whole workspace now builds and passes clippy for `x86_64-pc-windows-gnu`, with `sbarhived.exe` a GUI program that opens no console window and writes its stderr (including the notification lines) to `%LOCALAPPDATA%\SbarHive\logs\sbarhived.log`; the Linux tray library is a Linux only dependency, the Windows tray is a stub until S-046, and the Wayland activation hook is Unix only (built and unit tested on Linux, not yet verified on a live Windows system; S-052). «يُبنى مجلد العمل كله لويندوز، وتعمل خدمة صبار هايف دون نافذة طرفية وتكتب سجلها في ملف».
- Portal shortcut follow-ups (S-014f): a Settings switch "Register the drop shortcut with the desktop" turns the portal shortcut on or off and applies within seconds with no restart, on GNOME the daemon passes the activation token the portal gives it so the hive takes the drop under strict focus, and a key changed in the desktop's settings is kept, also after a restart (at once on KDE, on GNOME at the latest after logging out and back in). «خيار في الإعدادات يشغّل اختصار البوابة أو يوقفه دون إعادة تشغيل، وتأخذ الخلية الإفلات في GNOME برمز التفعيل، ويُحتفظ بالمفتاح الذي تغيّره في إعدادات سطح المكتب».
- Windows cross build and its checks (S-044): `scripts/windows/build.sh` builds `sbarhive.exe` for `x86_64-pc-windows-gnu` inside a 6 GB, two CPU systemd scope with two jobs (directly in CI), `check-dlls.sh` refuses an executable that imports any mingw `lib*.dll`, and `check.sh` runs Windows clippy on core, engines and the CLI with every target; Unix only tests now carry `cfg(unix)`, so the test programs build for Windows. CI adds `windows-cross` (the same scripts on Ubuntu with mingw-w64) and `windows-native` (the tests on Windows with FFmpeg), `make-iso.sh` packs the build and the test programs into an ISO for the test machine, and `run-tests.cmd` runs them there. «أمر واحد يبني صبار هايف لويندوز على لينكس بذاكرة محدودة ويرفض أي مكتبة mingw تحتاج إلى شحن، وCI يفحصه على ويندوز حقيقي، وصورة قرص تنقل الاختبارات إلى آلة ويندوز».
- Windows engines (S-043): LibreOffice and Ghostscript start suspended with no console window inside a kill-on-close job object, are put in the job and only then resumed, so cancelling, the timeout or the end of a run kills every process they started with `TerminateJobObject`, and the service dying closes the job and kills them too; on Windows a program counts as found only with an `.exe` or `.com` name, and LibreOffice, Ghostscript and FFmpeg are looked up in `PATH`, then their usual install folders, then the registry, never downloaded; a missing engine's error names it with its download page, the LibreOffice profile URL keeps the drive letter, and ffmpeg and ffprobe open no console window (built and unit tested on Linux, not yet verified on a live Windows system; S-052). «على ويندوز يجد صبار هايف LibreOffice وGhostscript وFFmpeg في أماكنها المعتادة دون إعداد، ويقتل الإلغاء كل ما شغّله المحرك، وتذكر رسالة المحرك الغائب اسمه ورابط تنزيله».
- Windows service start from the CLI (S-042): `sbarhive open` starts `sbarhived.exe` from the program folder with no console, in its own process group and outside the terminal's job (retried inside the job when breaking away is refused), so closing the terminal is meant to leave the service running (not verified live until S-052, and the Windows service builds from S-045); before `Open` and `Drop` the client lets the service take the foreground with `AllowSetForegroundWindow`, and `sbarhive daemon` runs the service and exits with its code; the CLI now builds for Windows. «على ويندوز يشغّل سطر الأوامر الخدمة لتبقى بعد إغلاق الطرفية (يُتحقق منه حياً في S-052)، ويسمح لها بالظهور في المقدمة قبل عرض الخلية».
- Windows folders and output naming without replacing (S-041): settings and user actions live in `%APPDATA%\SbarHive` and the service log folder will be `%LOCALAPPDATA%\SbarHive\logs` (written from S-045), falling back to `SHGetKnownFolderPath` when the variable is missing, one `Config::actions_dir()` replaces the two copies of the actions folder in the daemon and the CLI, and where hard links are unavailable (FAT, exFAT) the output is placed with `MoveFileExW` without replacing, so a file of the same name is never overwritten. «على ويندوز تُحفظ الإعدادات والإجراءات في مجلد التطبيقات المعتاد، ولا يستبدل الناتج ملفاً موجوداً حتى على قرص USB».
- IPC behind one transport (S-040): the client and the service reach each other only through `sbarhive_core::transport` (an endpoint, a listener that answers `AlreadyRunning` when a service already answers `ping`, and a stream whose read past its timeout fails with `TimedOut`), still the same socket and protocol on Linux, and on Windows a named pipe per user and session: an access list for the current user alone, no remote clients, one service through `FILE_FLAG_FIRST_PIPE_INSTANCE`, a client that refuses a pipe served by another user, and read timeouts cancelled with `CancelIoEx` (built and unit tested on Linux, not yet verified on a live Windows system; S-052). «العميل والخدمة يتصلان عبر واجهة نقل واحدة: مقبس لينكس كما هو، وعلى ويندوز أنبوب لا يفتحه إلا مستخدمك ولا يقبل اتصالاً من جهاز آخر».

### Changed
- Code cleanup from the review (S-029): one UTF-16 helper and one lock helper per crate, std `OwnedHandle` for the Windows job handles, an atomic one-shot flag for the read deadline, one helper for a missing engine program, the portal switch kept in the settings form, `Abortable` for stopping the portal client, and one sourced scope script for the Windows build scripts; no behaviour change. «تنظيف الشيفرة بعد المراجعة: نسخة واحدة من كل أداة مساعدة، دون أي تغيير في السلوك».

### Fixed
- Engine process trees (S-030): FFmpeg runs in the same kill-on-close job as LibreOffice and Ghostscript on Windows, so it stops when the service dies, and cancelling a video conversion kills every helper process FFmpeg started. «يعمل FFmpeg داخل شجرة عمليات واحدة: يتوقف مع توقف الخدمة في ويندوز، ويوقف الإلغاء كل عملية بدأها».
- Review fixes (S-028): a document on a Windows network share opens in LibreOffice through a `file://server/share/...` URL, a failing accept pauses 50 ms instead of spinning, a Windows client is served even when the next pipe instance cannot be made, a pipe read that brings data at its deadline keeps it, FFmpeg is looked up once per process, the Unix transport removes its own socket, and the Windows build scripts default to `${XDG_CACHE_HOME:-$HOME/.cache}/sbarhive-win-target` with their README in separate English and Arabic files. «إصلاحات المراجعة: تفتح ملفات مجلدات الشبكة في ويندوز، ولا تستهلك الخدمة المعالج عند خطأ الاتصال، ولا تضيع بيانات وصلت عند انتهاء المهلة، ولا مسار شخصياً في السكربتات».
- Hyprland release binds in the docs are non consuming (`bindrni`, `non_consuming = true`): a consuming release bind that ignores modifiers makes Hyprland swallow the bare key's press, so the documented `bindri = SUPER, Z` ate every Z typed anywhere and the `ALT_L` one every Alt; `tests/drop/hold_docs.sh` now fails on any consuming release bind in the docs. «ربط الترك الموثَّق في Hyprland صار غير مستهلِك، فلم يعد يبتلع كل حرف Z وكل ضغطة Alt».

## [0.3.3] - 2026-10-23 «اختصار البوابة»

### Added
- Drop shortcut through the global shortcuts portal (S-014e): on GNOME 48 and later and KDE 6 the daemon registers Super+Z itself through xdg-desktop-portal, with a consent dialog the first time, and the shortcut works by holding (`hold_ms`) like the manual binds; a refused dialog is remembered as `portal_shortcut = false` in config.toml, Hyprland can use `bind = SUPER, Z, global, io.github.m7mmad_omar.SbarHive:drop` as the alternative to the `exec` bind, and `docs/drop-shortcut.md` explains it in both languages. «تسجّل الخدمة اختصار الإفلات Super+Z بنفسها عبر البوابة في GNOME وKDE، فلا حاجة إلى ربطه يدوياً».

### Fixed
- Layer hive focus at KDE focus stealing prevention Extreme (S-027): on Hyprland, KDE and wlroots a normal show now asks for the keyboard before its full screen surface is first committed, so at Extreme a show with no activation token or a bogus one no longer takes the keyboard, while a show with a valid token, Hyprland and the lower KDE levels still get it and Esc still closes the hive. «لم تعد الخلية تأخذ لوحة المفاتيح دون رمز تفعيل صالح حين يكون منع سرقة التركيز في KDE على أقصى درجة».

## [0.3.0] - 2026-10-22 «الإفلات»

### Added
- Drop shortcut docs and budget (S-014d): `docs/drop-shortcut.md` explains, in Arabic and English, how to bind `sbarhive drop` to Super+Z (the default) in GNOME Settings, KDE System Settings and Hyprland, the Hyprland README adds the held left Alt binds (`sbarhive drop --hold` and `--release`), and a drop-mode show is measured on headless KWin at a median 51.3 ms to the first frame, taking no keyboard. «توثيق ربط اختصار الإفلات Super+Z في GNOME وKDE وHyprland».
- Hold a key to drop, and the dragged file in the drop hive (S-019e, S-019f): `sbarhive drop --hold` is the press of a held key and `sbarhive drop --release` its release, both returning at once; the daemon's long press gate shows the drop hive only once the key has been held for `hold_ms` (config.toml, 100 to 2000, default 400, read at every press), so a tap shows nothing, the release closes the hive without running anything, the drag leaving it does not close it while the key is held, and any close resets the gate; after a drag enters, the drop hive's centre shows the dragged file's thumbnail or kind icon, or the count of several. «تظهر خلية الإفلات بعد ضغط مطوّل على المفتاح وتختفي عند تركه، وفي مركزها صورة الملف المسحوب».
- Hive at the pointer on the overlay (S-019c, S-019d): on Hyprland, KDE and wlroots the hive now opens where the pointer or the dragged file is, its shape adapting near the screen edges, waiting at most 50 ms for the compositor to report the pointer and centring without it (Hyprland reports a still pointer only after it moves); a drop hive shown before the drag moves jumps once to the drag if it moves within 300 ms of the first frame, and otherwise stays centred with only the hive taking input, so a still pointer is never held, and `sbarhive drop --at X,Y` (for example `$(hyprctl cursorpos)`) places it there at once on the output holding that point; the window path (GNOME, a running screen reader) stays centred. «تظهر الخلية عند المؤشر أو الملف المسحوب ويتكيّف شكلها قرب حواف الشاشة».
- Screen reader rule and hive at an anchor maths (S-019a, S-019b): the hive becomes a window for a screen reader only when `ScreenReaderEnabled` is set and a reader owns `org.gnome.Orca.Service`, `hive_surface = "auto|layer|window"` in config.toml overrides the rule, every change of the choice prints one `hive surface choice: KIND, REASON` line, and `plan_at` computes a hive centred at an anchor whose shape adapts to the screen edges (not shown at the pointer yet). «الخلية نافذة لقارئ الشاشة فقط حين يعمل قارئ فعلاً، لا لبقية علم من إعداد GNOME».
- Drop on the hive overlay on Hyprland (S-020): in drop mode the overlay's full-output surface now takes the drag over the hive rectangle only (the hive subsurface takes none), so cells light up under a dragged file and a drop runs the action on Hyprland too; outside the hive drags and clicks still pass through. «على Hyprland تضيء الخلية تحت الملف المسحوب ويُنفَّذ إجراؤها عند الإفلات».
- Drop hive waiting text (S-014c): the hive shown by `sbarhive drop` now reads "Drop files here" («أفلت الملف هنا») in its centre until a drag enters, and with `SBARHIVE_DEBUG_FOCUS` the service prints one `drop cells: ID ...` line per enter with the cells built for the dragged files.
- File preview in the centre cell (S-018h): with no cell hovered the centre shows the selected file's cached thumbnail, decoded row by row and downscaled to the square inscribed in the centre hexagon before Slint and freed on every hide, else the kind icon with the format code; several files add two stacked hexagons and a count badge, mirrored in Arabic; the centre is read as the file name or the selection text, and the layout is unchanged.
- Overlay buffers, docs and suite (S-018f): hiding the overlay now frees every buffer of that show at once, the catcher's pixel included, instead of waiting for the compositor to release them; `docs/architecture.md` describes the layer and window paths and their choice rule, the Hyprland README gives an unverified layer rule that turns off the overlay animation, and `tests/overlay/run.sh` runs the whole overlay suite.
- Overlay colour scheme and cursor (S-018e): `SBARHIVE_COLOR_SCHEME` given to the service now decides the overlay colours ahead of the portal when `theme = "auto"`, and the overlay asks for the default arrow cursor (`wp_cursor_shape_v1`) on every pointer enter.
- Drop on the hive overlay (S-018d): `sbarhive drop` on the layer-shell overlay takes dragged files again, its drop receiver now bound on the overlay's connection to the hive surface, with clicks and drags outside the hive passing through.
- Hive overlay input and focus (S-018c): the activation token is sent once the overlay is mapped, `SBARHIVE_DEBUG_FOCUS` prints one `hive surface: layer|window X Y W H` line per show, and while a screen reader runs (`org.a11y.Status.ScreenReaderEnabled`) the next show is a window, back to the overlay when it stops.
- Hive overlay (S-018b): on compositors that offer wlr-layer-shell (checked on headless KWin) every hive show is a full-output overlay with the hive centred in it, no window frame or tiling, closed with Esc; GNOME and `SBARHIVE_SURFACE=window` keep the window, `SBARHIVE_SURFACE=layer|window` forces the choice.
- Centre picture lookups (S-018g): `sbarhive_ui::thumb` finds a valid cached freedesktop thumbnail for a file (GLib and Qt URIs, symlink targets, read only), its MIME type from shared-mime-info `globs2`, its kind icon (new monoline `file` icon) and format code.
- Overlay groundwork (S-018a): pure surface choice between a layer-shell overlay and a window, hive placement and buffer size per scale, evdev keys, colour scheme and cursor shape decisions in `sbarhive_ui::overlay`.
- Drop receiver (S-014b): on Wayland the hive shown by `sbarhive drop` takes a file dragged onto it, reads the files when the drag enters, builds their cells and runs the action of the cell it is dropped on, as a copy only; a drop elsewhere closes it and runs nothing.
- Drop groundwork (S-014a): `sbarhive drop [--token T]` asks the service for a hive that waits for dragged files, with a shared `text/uri-list` parser, drop point cell picking and the drop hive state machine.
- Fixed: `scripts/install.sh` stops a running daemon before replacing it, so an upgrade never leaves the old one running (the new one used to exit with "already running").
