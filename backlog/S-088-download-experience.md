# S-088 Download page: the demo film, a sample to try, and the honest warning
Status: approved under manager delegation (2026-10-26)

## Story
As someone downloading Kawaro for the first time, I want the download page to show the drag demo while my file downloads, hand me a sample image to try it on right away, and explain the Windows warning honestly, so that the first try succeeds instead of stalling at a scary dialog.

## Design intent (owner, 2026-10-26)
The owner asked that the download experience itself teaches: a video of the drag and the shortcut so the user understands, a prompt to try it while the download runs, a "Try it on an image" button, and a simplified settings pointer afterwards. Beautiful and systematic: the site design system, Arabic and English, RTL.

## Files
`site/download/index.html`, `site/en/download/index.html`, `site/build.py`, `site/media/` (the demo clip reuse and poster), `site/assets/` (the sample image), `tests/site/`, `scripts/site/check-links.sh` (only if new asset links appear).

## Landing order (from the goldfish reviews, 2026-10-26)
This page lands after S-083 (it includes the S-083 note and guide link; before S-083 exists the Windows block ships only the key-free warning-free text) and after or with S-087 (the walkthrough names S-087's welcome buttons by the labels S-087 AC4 and AC5 fix; before S-087 lands the walkthrough names the tray menu instead and is updated in the same release). No absolute wording depends on a story that has not landed.

## Acceptance criteria
- AC1: the Arabic and English download pages show the demo film (the existing hero demo clip, autoplay muted and looping with native controls, per the S-070 hero convention) next to the download buttons, with a caption naming the flow: drag a file, hold the drag key, drop on the cell. The caption names no specific key until the measured contracts exist: it reads the key from the S-084 manager decision line for Windows and the S-075 measured contract for Linux (today only the Super+Z portal trigger is measured on Linux, so a page built before those lines exists ships the key-free wording), and a page build that has neither may ship only the key-free wording (drag, drop on the cell). Film and caption must teach the same thing: if the filmed clip shows a key that the caption does not name (the S-068 clip predates the S-084 measurement), the page either ships a re-cut clip without key close-ups or masks the key in the caption step; a page where the film teaches Alt and the caption names another trigger fails this criterion. Under reduced motion the page shows the poster and the numbered caption steps instead of the moving film.
- AC2: beside the film, a numbered "after the download" walkthrough in Arabic and English: install, open Kawaro from the right click menu or the icon, drag a file while holding the drag key (wording follows the same measured-key rule as AC1: if the S-084 winner is the right-button drag, the step says drag with the right button and holds no key), drop on the cell of the action, the result appears next to the original. Each step names the control the user will actually see (S-087 welcome buttons included).
- AC3: a "Try it on an image" / «جرّب على صورة» button downloads a small sample image from the site (a few hundred kilobytes at most, licence clean, generated from the same fixture S-087 embeds, so the app and the page always show the same sample) through the browser's normal download flow (the browser chooses the folder or prompts, the page never assumes one), and the accompanying line tells the user to drag that file onto the hive to get a result beside it. The button works in both languages and has a descriptive accessible label.
- AC4: the Windows download block includes the S-083 note and guide link (S-083 owns their text); this page never claims signing that has not happened, never claims the warning disappears, and never asks the user to disable SmartScreen. Once S-083's owner step runs and the build is genuinely signed, the page may say so as S-083's note text says it.
- AC5: the site keeps every existing security header and language switch line; no long dashes anywhere in the touched pages; `PATH=/usr/bin:$PATH bash tests/site/run_heavy.sh` passes, `scripts/design-lint.sh` passes, and the pixel tests hide the film before comparison (the known convention for film elements).
- AC6: one CHANGELOG line in both languages.

## Manager decision (2026-10-27)

- D1 (the film and the caption teach the same thing; amends AC1): the shipped hero clips name no key. Verified two ways before this decision: the film sources (`video/intro-hero/index.html` and `video/intro-hero-en/index.html`) draw one keycap whose label is «اختصارك» / "Shortcut" and caption pills that read «واضغط اختصارك،» / "press your shortcut,"; and OCR of the shipped `site/media/hero*.webm` frames finds no key name (no Alt, no Ctrl, no Super) anywhere in the clip. So the AC1 failure bar (the film teaches Alt while the caption names another trigger) cannot fire with these clips and the re-cut remedy is not needed. The caption masks the key exactly as the film does: its flow step reads "Press your shortcut" / «اضغط اختصارك» like the film's own pill, and one line under the steps fills that generic key with the measured values of D2, including the Windows case where no key exists. If a future re-cut names a key on screen, this page updates in the same release and the caption line names that same key.
- D2 (which keys the page names today; amends AC1 and AC2): the measured lines exist on build day. Windows: the S-084 manager decision D3 (2026-10-27) names the right-button drag with no key held, so every trigger step says drag with the right mouse button and no key is held, and names no Windows key. Linux: the S-075 per-desktop contract (2026-10-26) measures only the named portal fallback Super+Z (the spike control, 21 PASS and 0 FAIL on each desktop), and `docs/drop-shortcut.md` with `docs/guide/shortcuts.md` name Super+Z as the default shortcut of the shipped build, so the page names Super+Z as the Linux shortcut. No line on this page names Alt (the S-075 rule against unmeasured claims; Alt through the portal is disproven). When S-075 lands its native per-desktop contract naming another trigger, these lines read the new contract and update in the same release.
- D3 (layout; fixes the AC1 and AC2 placement): the download page grows one teaching stage inside its download section: one column holds the film with its numbered caption and the Try button, the other column holds the download slabs and, beneath them, the numbered after-the-download walkthrough. At wide widths the two columns stand side by side, so the film is next to the download buttons and beside the walkthrough; on small screens the blocks stack in reading order (slabs, walkthrough, film, Try). The reduced-motion variant replaces the moving film with its poster and keeps the numbered caption steps.
- D4 (the sample image; amends AC3): the one sample is `tests/fixtures/images/kawaro-sample.png`, written by `scripts/site/make-sample-image.py` (pure standard library, deterministic, colours from the site block of `design/tokens.json`, the story name in its header), and `site/assets/kawaro-sample.png` is the same bytes; a test asserts the two files are identical so the app (S-087 embeds the fixture) and the page always show the same sample. S-087 embeds exactly this fixture path.
- D5 (the honest warning stays one text; amends AC4): S-083 owns the note text in the Windows slab, so this page adds no second warning narrative that could drift from it. The walkthrough's install step names the dialog the user will really see ("Windows protected your PC") and its two buttons (More info, Run anyway) and points at the note under the Windows buttons and the guide, so the first try does not stall at the dialog. The AC4 claim scan covers the note and every new line of this page.
- D6 (the S-087 substitution of the landing order): S-087 has not landed in this build (no welcome window exists in the tree), so the walkthrough names the tray menu where S-087's welcome buttons will be named: the step that opens Kawaro points at the Kawaro menu beside the clock and its Settings item. When S-087 lands, the walkthrough names its buttons and the test that pins this wording updates in the same release.
- D7 (amends the D3 small-screen order): on small screens the blocks stack as the download slabs, then the film with its caption and the Try button, then the walkthrough, so the film stays next to the download buttons and the walkthrough follows the film in reading order too. At wide widths the layout is as D3 states: the slabs and the walkthrough share one column and the film column stands beside them. No test asserted the earlier order, so only the D3 text changes.
- D8 (rule 8 re-baseline of stale S-063 assertions, recorded here because this chain must leave the site heavy runner green): `tests/site/test_s063_static.py` already failed three assertions at main d44a05f (proved by running the suite against a `git archive` of main: the same three failures, no S-088 code involved). The S-017 glass work moved the app-keys hash of `design/tokens.json` and gave the site block the eight-digit glass-2 and glass-3 colours, and the S-083 note rule sat in `download-slab.css` under the bare `.download-note` selector the component-ownership check rejects. Each assertion keeps guarding on the new values: the hash constant is refreshed to the current app keys and still fails on any later change, the colour check now requires six digits for every key and eight for the glass pair only, and the note rule is scoped under `.download-slab` so the component-ownership check passes unchanged. One S-088 violation found in the same run is fixed in the code, not the test: `.walk .step-cell p` styled a component class from `pages.css` and is removed.
