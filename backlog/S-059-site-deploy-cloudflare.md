# S-059 Deploy the website and docs to kawaro.sbarah.com on Cloudflare
Status: done

Decided in ADR 0007: Workers Static Assets with no Worker script, built and deployed by Cloudflare Workers Builds, so no Cloudflare secret lives in GitHub. This story is the repository side; the Cloudflare and GitHub settings are in "Owner steps". Estimate one working day; if it runs over, AC6 and AC7 move to S-060. Not a Rust change, so no crates are touched.

## Story
As the maintainer, I want the site and docs served from `https://kawaro.sbarah.com` with strict headers and a checked upload set, so that a public repository cannot leak a credential or publish a file that should not be public.

## Acceptance criteria
- AC1 (`wrangler.jsonc`): the file at the repository root parses with `jq` (no comments) and has `name` equal to `kawaro-site`, `assets.directory` equal to `./site`, `workers_dev` equal to `false`, a `compatibility_date` that matches `YYYY-MM-DD` and is not after the build date, and none of the keys `main`, `account_id`, `vars`, `kv_namespaces`, `r2_buckets`, `d1_databases`, `services`, `routes`, `secrets`. No value in it matches `[A-Fa-f0-9]{32}` (an account id) or `token`.
- AC2 (`site/_headers`): the rule `/*` carries exactly these 8 headers with the values in ADR 0007 section 7: Content-Security-Policy, Strict-Transport-Security (`max-age=86400; includeSubDomains` or `max-age=31536000; includeSubDomains`, never `preload`), X-Content-Type-Options `nosniff`, Referrer-Policy `no-referrer`, Permissions-Policy, Cross-Origin-Opener-Policy `same-origin`, Cross-Origin-Resource-Policy `same-origin`, X-Frame-Options `DENY`. The CSP contains `default-src 'none'`, `frame-ancestors 'none'`, `base-uri 'none'`, `form-action 'self'`, `object-src 'none'`, and does not contain `*`, `http:`, `https:`, `data:`, `unsafe-eval` or `script-src` with `'unsafe-inline'`. Only the paths `/pagefind/fragment/*`, `/pagefind/index/*` and `/pagefind/*.pf_meta` have `immutable`; `/fonts/*` has `max-age=2592000`. The file has at most 100 rules and no line over 2000 characters (Cloudflare limits).
- AC3 (built output matches the CSP and the domain): after `scripts/build-site.sh` there are 0 occurrences of `github.io` and 0 of `m7mmad-omar.github.io` under `site/` (html, xml, txt, md); every canonical, hreflang, `og:url` and sitemap `<loc>` starts with `https://kawaro.sbarah.com/`; `site/.nojekyll` does not exist. In every built `.html` file: each inline `<script>` that is not `type="application/ld+json"` or `type="application/json"` has its SHA-256 listed in the CSP of `_headers` (and the number of such scripts is 1); there is no `on*=` attribute; every `style=` attribute matches `^--[a-z-]+:-?[0-9.]+;?$`; no `src`, `href` of `<link>` or `import` points to an origin other than `kawaro.sbarah.com`. A headless Chromium run (the private pane used in S-056) loads `/docs/start/`, `/en/docs/install/` and the search box, searches `install` and `تثبيت`, and reports 0 CSP violations and at least 1 result for each query when served with the `_headers` rules (`wrangler dev --local`).
- AC4 (`.assetsignore` and `scripts/site/check-deploy.sh`): `site/.assetsignore` lists at least `build.py`, `*.py`, `*.sh`, `*.map`, `*.toml`, `*.lock`, `.env*`, `*.key`, `*.pem`, `.git*`, `.nojekyll`, `node_modules/`, `backlog/`, and does not list `*.md` or `.*`. The script has `--build` (runs `scripts/build-site.sh`, then checks) and a default check-only mode, uses its own matcher (not `wrangler deploy --dry-run` output), prints `upload set: N files` and exits 0 on the real tree, where N is at least 40 and the set includes `docs/start/index.html`, `en/docs/start/index.html`, `llms.txt`, `docs/start.md`, `.well-known/security.txt` and `pagefind/pagefind.js`. It exits 1 and prints the path when a temporary copy of `site/` contains any of `build.py`, `.env`, `.git/config`, `app.js.map`, `notes.toml`, `x.key`, a file with a `-----BEGIN PRIVATE KEY-----` line, a file of 26 MiB, or an extension outside the allowlist in ADR 0007 section 6. It exits 2 with a message when `site/_headers` or `wrangler.jsonc` is missing.
- AC5 (`security.txt`): `site/build.py` writes `site/.well-known/security.txt` with `Contact:` equal to `https://github.com/M7MMAD-OMAR/kawaro/security/advisories/new`, `Expires:` an RFC 3339 UTC date between build date plus 170 and plus 190 days, `Preferred-Languages: en, ar`, `Canonical: https://kawaro.sbarah.com/.well-known/security.txt`, `Policy:` the `SECURITY.md` URL on GitHub; it contains no `mailto:`.
- AC6 (workflows): a new `.github/workflows/site-check.yml` runs on `pull_request` and on `push` to `main`, runs `scripts/site/check-deploy.sh --build`, has top level `permissions: {}` and job `permissions: contents: read`, `actions/checkout` with `persist-credentials: false`, and every `uses:` pinned by a 40 hex character SHA with the version in a comment. Across all files in `.github/workflows/`: 0 matches of `pull_request_target`, 0 of `CLOUDFLARE`, `wrangler-action` or `secrets.` (apart from `release-signing` secrets in `packages.yml`, which stay in the job `update-manifest` only).
- AC7 (repository rules): `.github/CODEOWNERS` assigns `.github/`, `site/`, `wrangler.jsonc`, `scripts/site/`, `docs/adr/` and `packaging/keys/` to `@M7MMAD-OMAR`. `.github/dependabot.yml` has the `github-actions` ecosystem with weekly updates, directory `/`.
- AC8 (`docs/site-security.md` and `docs/site-security.ar.md`): both start with `[English](site-security.md) | [العربية](site-security.ar.md)`. They state the controls of ADR 0007 sections 3 to 5 and 7 to 10 (hosting, no secret in GitHub, token scope and expiry, headers, DNS and TLS, privacy, rollback) and the token rotation steps, with placeholders (`<ACCOUNT_ID>`, `<ZONE_ID>`, `<EXPIRY_DATE>`) and no account id, email or machine name. Each has the same 9 level-2 headings (`grep -c '^## '` equal in both files).
- AC9 (finish): `CHANGELOG.md` has one new line in English and Arabic for S-059; `scripts/design-lint.sh` and a search for long dashes over the diff both give 0 matches; the section "Owner steps, not automated" below is copied unchanged into `docs/site-security.md` as its last section.

## Owner steps, not automated
Only the owner can do these; the repository work above does not need them to pass, but the site is not live until they are done. Use placeholders in anything written to the repository.
1. Confirm the `sbarah.com` zone is on your Cloudflare account and active, and that no DNS record named `hive` exists yet.
2. Turn on 2FA (a hardware key or passkey if possible) on the Cloudflare and GitHub accounts, store the recovery codes offline, and review active sessions.
3. In GitHub: enable secret scanning and push protection, private vulnerability reporting, Dependabot alerts; set "Approval for all outside collaborators" for workflows from forks; default `GITHUB_TOKEN` permission to read only; on `main` block force pushes and deletion and require linear history; disable GitHub Pages for the repository.
4. In Cloudflare, Workers Builds: connect the GitHub App to this single repository; production branch `main`; build command `scripts/site/check-deploy.sh --build`; deploy command `npx wrangler@<pinned version> deploy`; build variables `PYTHON_VERSION` and `NODE_VERSION` (not secrets); non production branches build as preview versions.
5. Replace the default build token with a custom token for one account (`<ACCOUNT_ID>`) with only the Workers permissions a deploy needs (confirm the names in the dashboard), an expiry date (`<EXPIRY_DATE>`, at most 12 months) and a calendar reminder 30 days before it. Do not store it anywhere else; use `wrangler login` for manual work.
6. First deploy: on a branch build or manually, with `workers_dev` temporarily on, open the `workers.dev` address; check headers (step 9), search in both languages and `/.well-known/security.txt`; then turn `workers_dev` off.
7. Attach the custom domain `kawaro.sbarah.com` in the dashboard (Workers, Settings, Domains and routes). Check the other services on `sbarah.com` first, then set SSL Full (strict), Always Use HTTPS, minimum TLS 1.2, DNSSEC (DS record at the registrar) and the proxy on; no wildcard records; CAA only after reading Cloudflare's current guidance.
8. After one week with no problem, change HSTS to `max-age=31536000; includeSubDomains` in `site/_headers` (no `preload`).
9. Verify with an online checker (for example Mozilla Observatory and securityheaders.com) that the headers match AC2 and the grade is at least A, and with an SSL test that TLS 1.0 and 1.1 are refused.

## Manager decision (2026-10-26): amendments that win over the criteria above

The live site already deploys by hand from a staged folder, and that folder is a stricter upload set than `./site`. The criteria are amended as follows; every other criterion stands as written.

- D1 (amends AC1): `assets.directory` is `./.deploy-out`, the folder `scripts/prepare-site-deploy.sh` stages from `site/`. `workers_dev` is `false`. `routes` is allowed and must equal exactly `[{"pattern": "kawaro.sbarah.com", "custom_domain": true}]`, because the domain is attached through it today and removing it before the owner moves deploys to Workers Builds could detach the domain. Every other forbidden key in AC1 stays forbidden, and the no account id and no `token` rules stay.
- D2 (amends AC2 and AC5): `_headers` and `.well-known/security.txt` are generated into the staged folder by `scripts/site-headers.py` (no hand kept `site/_headers`). The tests run `scripts/prepare-site-deploy.sh` and read `.deploy-out/_headers` and `.deploy-out/.well-known/security.txt`. The values required by AC2 and AC5 apply unchanged, including `Expires:` computed from the build date.
- D3 (amends AC3 and AC4): checks that AC3 and AC4 make on `site/` apply to the staged folder `.deploy-out/` (the upload set). `site/.assetsignore` is the source and is copied into the staged folder. `check-deploy.sh --build` runs `scripts/prepare-site-deploy.sh`, then checks; check-only mode reads the `assets.directory` of `wrangler.jsonc`; a path argument overrides the folder (used by the planted file tests). The headless check may serve the staged folder with `wrangler dev --local` or with a local test server that applies the staged `_headers` rules to every response.
- D5 (amends AC3, 2026-10-26 after the tester's question): a `style=` attribute may carry one or more numeric custom properties, each `--name:number;`; the whole value must match `^(--[a-z-]+:-?[0-9.]+;?)+$`. Only custom properties with numbers, so no colour, url or expression can enter through `style=`. The manager changed the one regex in the test accordingly. `Policy:` in AC5 is `https://github.com/M7MMAD-OMAR/kawaro/blob/main/SECURITY.md`; the machine name in AC8 is the host name.
- D6 (2026-10-26, from the implementation): the tab icon was an inline `data:` SVG (S-061, so the demo made no request after load). AC2 forbids `data:`, so the icon is now the same origin `/favicon.svg`; Chromium fetches it once after load. The S-061 test `test_AC7_zero_network_requests_after_load` now allows exactly that one same origin request, and the S-061 test `test_AC12_csp_unchanged` asserts the S-059 values instead of the old ones. `webp` joins the extension allowlist (ADR 0007 section 6 updated) because the S-063 art is WebP. The manager made these test edits, not the implementer.
- D4: `docs/site-security.md` records why `routes` stays and the owner step after which it is removed (Workers Builds with a token without zone permissions, domain attached in the dashboard).
