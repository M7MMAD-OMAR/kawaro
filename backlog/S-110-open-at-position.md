# S-110 `kawaro open --at X,Y` and the Hyprland launcher pass the pointer
Status: done (private Hyprland measurement is the follow-up S-110b, not run; KDE and GNOME stay in S-077b)

## Story
As a Hyprland user opening a copied selection with `kawaro-open-selection`, I want the hive to appear at my pointer, so that it opens where I am working instead of centred on the screen. This is S-077a of `docs/backlog-triage-2026-10-31.md`, split from S-077 so that every criterion runs in the fast loop (no compositor).

## Acceptance criteria
- AC1 (parse): `kawaro open --at X,Y` uses the same parser and the same meaning (global logical coordinates) as `kawaro drop --at`. Inputs `400,500`, `1198, 1800`, `-1280.5,300.25` give `(400,500)`, `(1198,1800)`, `(-1280.5,300.25)`. Inputs `abc`, `1`, `1,2,3`, `nan,1`, `inf,1`, empty exit with code 2, name `--at` in stderr, and send 0 requests.
- AC2 (IPC): `kawaro open --at 400,500 --token T FILE` sends exactly 1 `Request::Open` with that file, token `T` and `at = [400,500]`. Without `--at`, `at` is None. Negative and fractional values survive a serialize then deserialize round trip unchanged.
- AC3 (compatibility): JSON `{"op":"open","files":["/a"],"token":null}` without the field (an old client; use the exact tag shape of `ipc.rs`) deserializes to `at = None`. JSON with the field deserializes to `Some`. A new client's JSON for `at = None` still parses with the field absent or null. The field is `#[serde(default)]`. The existing `Drop`, `Run` and `Ping` JSON tests pass unchanged.
- AC4 (daemon): with a fake presenter, `server::open(state, files, token, Some((400,500)))` calls the presenter once with `at = Some((400,500))`, and with `None` calls it once with `at = None`. The seam is small (a trait or function parameter); the production presenter is the existing `ui::present`.
- AC5 (placement decision): a pure function in `crates/ui` (the one that picks the layer anchor, not a new maths copy) returns for a normal show (drop false) with `at = Some(p)` the anchor `p` at once, so `plan_at` is used and there is no centred first frame. With `at = None` it returns exactly what it returns today (the wait for a pointer event until the 50 ms deadline, then centred). Table test covers `at` present and absent, drop true and false, and the S-105 `remap_at` results for drop shows are unchanged (existing tests pass without edits). A normal show with `at` sets no drop probe, hold or later move (assert the mode flags).
- AC6 (window path): on the ordinary window path (non layer) `at` has no effect: the same test asserts the window plan equals the plan for `at = None`.
- AC7 (launcher): `integrations/linux/hyprland/kawaro-open-selection.sh` reads `hyprctl cursorpos` exactly once and runs `kawaro open --from-clipboard --at X,Y` with X and Y as printed, with the Ctrl+C and delay steps unchanged. `bash -n` (or `sh -n`) passes. With a stub `hyprctl` printing `640, 360`, `-1280, 5` and `10.5, 20.25`, the logged final call is `kawaro open --from-clipboard --at 640,360`, `--at -1280,5` and `--at 10.5,20.25` (spaces after the comma may be kept or removed, but one form is asserted). With a stub that exits 1 or prints `nothing`, the script exits non-zero, writes one line to stderr, and the log has 0 `kawaro open` calls (no `0,0` and no centred substitute). `hyprctl` appears only in the script, in no Rust file.
- AC8 (docs): `kawaro open --help` documents `--at` in the same words as the drop option. `integrations/linux/hyprland/README.md` and `README.ar.md` both describe the pointer position in the launcher, and a test checks both mention `--at` and `hyprctl cursorpos` (parity, 2 of 2). `CHANGELOG.md` has one line naming S-110, in English and Arabic. `scripts/design-lint.sh` finds 0 long dashes in the touched files.
