# S-087 First-run welcome: the demo, Try on an image, and Settings
Status: done (2026-10-27, chain reviewer PASS and merged to main via cdac007; shipped with 0.4.0).

## Story
As a new user who just installed Kawaro, I want the first window to show me the drag flow, let me try it on a sample image with one click, and open the simplified Settings, so that I understand the app before I touch my own files.

## Design intent (owner, 2026-10-26)
The owner asked for a beautiful, systematically built first experience: a demonstration of the drag and the shortcut so the user understands it, a "Try it on an image" button, and a Settings entry that leads to the simplified settings page of S-076. Beautiful means the design system: tokens only, Material 3 controls, Arabic and English with RTL mirroring, reduced motion respected. Nothing technical in any visible string.

## Files
`crates/ui/ui/welcome.slint` (new), `crates/ui/src/lib.rs` (window construction alongside `SettingsWindow::open` in `crates/ui/src/settings.rs`), `crates/ui/build.rs` (the demo frames and the sample image as embedded resources), `crates/daemon/src/ui.rs` (a `present_welcome` beside `open_settings`, which lives here), `crates/daemon/src/server.rs` (the first-run branch of the `Settings` request), `crates/daemon/src/tray/` (a "Get started" item), `tests/fixtures/` (the sample image source), snapshot references under the existing snapshot directory.

## Acceptance criteria
- AC1: the welcome window opens on a one-shot `welcome_seen` marker in the config, not on "no config file yet": a config written by any other path (a portal denial save, a Settings save, an updater write) must not hide the welcome, and the welcome sets the marker only after it is actually shown. With the marker set, `kawarod settings` and `kawaro settings` open the S-076 settings window exactly as S-086 AC1 requires. The tray menu gains a bilingual "Get started" / «ابدأ هنا» item that opens the welcome window at any time regardless of the marker. D1 below amends S-086 AC1 for the first-run case only.
- AC2: the welcome window shows a silent looping demonstration of the whole flow: dragging a file, activating the trigger, the hive appearing (at the pointer where the platform puts it there, centred where it does not, matching what the user will really see), dropping on a cell, the result appearing next to the untouched original. The demonstration is built from pre-rendered frames or shapes inside Slint and adds no runtime engine or decoder to the base install; the embedded frame set and sample image together stay under 2 MB in the shipped binary. With reduced motion on, it shows one static frame plus the caption steps instead of looping.
- AC3: the demonstration captions are Arabic and English and name the trigger exactly as the measured contracts define it: the S-084 winner for Windows and the S-075 measured contract for Linux, including the wording "drag with the right button" if that is the winner. When the configured key and the live registration differ (the portal fallback of S-075), the caption names the key that actually works on that desktop, read from the registration result, not the config value. Until both contracts exist in their story files the demonstration uses key-free wording (drag, drop on the cell). Captions are available as accessible text, not only drawn pixels.
- AC4: "Try on an image" / «جرّب على صورة» copies a bundled sample image to a writable temporary folder and opens the hive for exactly that one file through the same request path as the Explorer menu entry, so one click lands the user on a live hive and converting writes the result next to the untouched sample. The button is invokable by pointer and by keyboard and has a descriptive bilingual accessible label.
- AC5: "Open Settings" / «افتح الإعدادات» opens the S-076 settings window; no string in the welcome window contains portal, daemon, registry, config, IPC or token.
- AC6: four approved snapshots `welcome-{ar,en}-{light,dark}.png` show the demonstration area, both buttons and no technical wording; element order is mirrored in Arabic; every colour, spacing, radius and duration comes from `design/tokens.json`; no shadow, no gradient, no one-sided border; `scripts/design-lint.sh` and the no-long-dash check pass.
- AC7: the window appears within 1 s of the click that opens it on the S-079 reference machine (the same budget as S-086 AC2; the 150 ms budget of the hive does not apply to a cold-started settings-class window), with the first frame and captions already drawn; one CHANGELOG line in both languages.

## Manager decision (2026-10-27)

- D3 (frames pipeline, S-087a; amends AC2's placement clause into assets): the frames are rendered once by the checked-in generator `scripts/gen-welcome-frames.sh` (story name S-087 in its header) running `crates/ui/examples/welcome_frames.rs` in a private headless KWin, like `crates/ui/tests/snapshots.sh` does for the snapshots. The scene `crates/ui/ui/welcome-frames.slint` is built from `components/hex-cell.slint`, the same hive cell component the real hive uses, so the frames show the hive users will really see. Four sequences are rendered because AC2 demands the real placement and the design demands tokens: the hive at the pointer (Windows, X11 and the layer path) and the hive centred (the Wayland window path), each in the light and dark token schemes, 16 frames each, named `crates/ui/resources/welcome/frame-{lp,lc,dp,dc}-NN.png`. The runtime window plays the sequence its own hive placement would produce (`kawaro_ui::welcome::demo_hive_centred`, mirroring the layer decision) in its own scheme. The budget test counts every embedded frame plus the sample image against the 2 MB of AC2. `crates/ui/resources/welcome/README.md` is the licence note: every file there is generated by that script from the project's own components and tokens under the repository licence, and no frame asset may be committed without that generator.
- D4 (captions, AC3): the trigger step of the captions is resolved by pure logic in `kawaro_core::welcome` from the registration result only: `Registration::RightDrag` (the S-084 D3 winner on Windows) gives the wording "Drag with the right button" / «اسحب بالزر الأيمن», which names no key; `Registration::Native(key)` and `Registration::Fallback(key)` give a hold-while-draging step naming exactly that key; `Registration::Unbound` gives the key-free wording of AC3 (drag, drop on the cell). The configured `drop_key` is never an input to the caption code, so the caption cannot show the config value instead of what works (AC3). The daemon supplies the registration it actually performed: on Windows the fixed S-084 trigger, on Linux what the GlobalShortcuts portal bound (`Registration::Fallback` with the reply's trigger description) or `Registration::Unbound` when nothing is bound; S-075's native paths will supply `Registration::Native` when they land. The caption is resolved when the welcome window opens, so a registration that changes later applies at the next open. The five caption steps and the window strings live in `kawaro_core::welcome::strings` and `captions` in both languages; the trigger step is `steps[1]` of five.
- D5 (marker semantics, AC1): `welcome_seen` is a one-shot key written only as `welcome_seen = true`: `Config::save_to` skips it while it is false, so no other write path (a portal denial save, a settings save, an updater write) can create a marker that hides the welcome. The welcome writes it in the event loop closure after the window is actually shown, and only there. The routing is the pure `kawaro_core::welcome::route`, and `Request::Settings`, `kawarod settings` and `kawaro settings` all go through `server::settings`, which calls it. The tray item "Get started" / «ابدأ هنا» opens the welcome window directly, ignoring the marker.
- D6 (try flow, AC4): `kawaro_ui::welcome::install_sample(dir)` writes the bundled sample as `sample.png` and the daemon's `try_sample` opens the hive through `server::open`, the exact function behind `Request::Settings`'s sibling `Request::Open`, so the one-click path is the Explorer menu path. The bundled sample is `tests/fixtures/images/welcome-sample.png`, embedded by `crates/ui/build.rs` (`welcome_resources.rs`), with `scripts/gen-welcome-sample.sh` as its generator.
- D7 (superseded tests, rule 5b): adding the tray item changes `text::menu_labels` and the Windows menu, so the older assertions that pin the label list (`update_tests.rs` AC5 list, `shell_logic_tests.rs` `s054b` length and sync tests) are updated to carry "Get started" at index 1 in both languages; every other assertion in them is kept.
- D8 (AC6 snapshots): the four `welcome-{ar,en}-{light,dark}.png` references are rendered by `crates/ui/tests/welcome_snapshots.sh` in the private compositor and approved here under the delegated screenshot approval; the CI rows of AC6 cover only static checks (the four files exist and are PNGs, RTL mirrors the button order, the forbidden words, design lint and the dash check), and no CI green is ever claimed for the snapshot row.
- D9 (amends D8's approval clause): no image inspection capability was available in this chain, so the four references were rendered in the private compositor and verified mechanically instead of by eye: OCR of the renders shows the title, the caption step and both buttons in English, the Arabic caption in Arabic, the primary button sits mirrored between the two languages, light and dark renders are distinct, and the OCR text carries none of the forbidden words. The human visual approval of the four references stays with the maintainer or the manager and is recorded as pending, not done.
- D10 (tester repairs of rule 5b, every assertion kept): the forbidden-literal scan of `crates/ui/ui/welcome.slint` skips import and asset paths (the generated `tokens.slint` file name contains "token"), the distinct caption steps check converts the array with `to_vec` (`dedup` is a Vec method), the `glass_tokens.rs` fixture tree gains the `resources` and `tests` directories the welcome build reads, and the Config constructions in the new tests start from a struct literal so clippy's `field_reassign_with_default` stays quiet (the S-084 construction pattern).

## Out of scope
- Video playback or a video engine in the app (the base install stays light; the film lives on the download page, S-088).
- Changing the simplified settings content (S-076 owns it), the drag key registration contract (S-075 and S-084 own it).
- Any auto-opened window without a user click (focus stealing is the top risk; the welcome window opens only from an icon click or the tray item).
