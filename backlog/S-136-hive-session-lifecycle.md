# S-136 End hive sessions once, without stale reopen or duplicate submission
Status: done

## Story
As a user, I want one drag or explicit open to own one selection until I run or dismiss it, so that dropping cannot submit and reopen the same files, and an old callback cannot affect my next selection.

## Acceptance criteria
- AC1 (exclusive drop effects): in choose-during-drag, a valid cell drop submits exactly one job and opens zero normal hives; an empty/disabled-cell drop submits zero. In drop-first, enter shows zero action cells; dropping anywhere closes the catcher before exactly one normal hive opens, submits zero jobs until an enabled action is chosen, then submits exactly one. Unsupported/empty/rejected drags submit zero and never reuse earlier files.
- AC2 (terminal ownership): commit or dismissal invalidates that session before invoking external callbacks. Duplicate Drop, Enter, Motion, Leave, Release, Cancel, click, keyboard activation, options Run and delayed close/open callbacks from that session cause zero further submissions or shows. Pending files, dragged payload, preview, hover and options state cannot be reused after terminal close. A drop-first handoff transfers its selection once to the normal hive; Release from the old hold cannot dismiss it.
- AC3 (replacement and entry paths): a fresh explicit open creates new ownership, even for the same file; stale session A callbacks cannot submit, clear, hide or reopen session B. The selected mode is captured for every new drop show, including the held-key timer and non-held IPC path, after config reload. Context-menu/CLI open, clipboard shortcut, drop-first, choose-during-drag and stage 2 Run share the same ownership invariant on layer and ordinary-window paths, including Windows/X11 adapters. No compositor-specific or system-binding workaround.
- AC4 (hold and recovery): holding Alt after commit never rearms the consumed drag; Escape, cancellation, release-before-drop and timeout submit zero and leave no reusable selection. Preserve the existing bounded no-drag pointer-probe rearm, but never rearm a consumed/cancelled drag. A subsequent release and fresh press/drag works exactly once without daemon restart. Existing placement, focus policy, reduced motion and the under-150 ms invocation/drop-first show budgets remain unchanged.
- AC5 (evidence): regression tests exercise production event dispatch plus daemon callback wiring, not only a detached plan helper. Record callback order, payloads, presenter calls and queue submissions. Add one bilingual changelog entry; run scoped fmt, clippy, touched-crate tests and design lint under repository resource limits in subsequent chain steps.

## Likely cause and private reproduction plan
Code-read hypothesis, not a runtime reproduction: [Inner::drag](../crates/ui/src/lib.rs#L931-L959) calls choose for Running(i), then calls on_drop_first on every Drop with dragged files, without testing mode or accepted transition. [Daemon handoff](../crates/daemon/src/ui.rs#L179-L192) calls [open_with](../crates/daemon/src/server.rs#L104-L136), repopulating pending after submission. The held show [gate_tick](../crates/daemon/src/ui.rs#L518-L538) also omits mode application present in [non-held show](../crates/daemon/src/ui.rs#L419-L427); Hive initially uses ChooseDuringDrag. This explains the full hive followed by a reusable normal hive; hidden preview details remain unverified.

Extend the existing [private Hyprland harness](../tests/hyprland/repro.sh) and [Alt-drag scenario](../tests/hyprland/altdrag.sh): isolated HOME/config/runtime/socket and private D-Bus/portal/tray, temporary files under HOME, never the live desktop. Use a URI-list drag source and disposable image; drag first, hold Alt, move onto an enabled cell, drop while Alt remains down, then move/release/click the old cell and observe 15 s. Capture screenshots, event order, mode, submit IDs, output count and source hash. Repeat both modes, Alt-first/drag-first, fresh second drag, layer/forced-window, then private KWin and X11 harness equivalents where available. Alt is a native Hyprland binding, not a claimed portal trigger; use a supported portal chord for that path. Private evidence does not close real GNOME/KDE focus story S-082.

## Out of scope
Engine/action changes, output-name deduplication, file-path bans on legitimate later runs, dependency/toolkit upgrades, global binding edits, live desktop tests and release/install work.
