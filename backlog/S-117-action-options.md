# S-117 Typed action options in core, declared in the action TOML
Status: done (2026-11-04)

## Story
As a user, a script and a local agent, I want one action to accept a different value for one run, declared once in the action file, so that the hive customization, the CLI and MCP all read the same definition instead of inventing three. This is the data and core half of the owner's customization request (ADR 0012). It adds no UI and changes no IPC.

## Facts found while planning
- `ActionDef.params` is an untyped `toml::Table` (`crates/core/src/action.rs:69`) and `Request::Run` carries no params. There is no per-run override anywhere.
- `action_impl::validate` already fails an action load with `RegistryError::Parse`; the options reach it through the same path.
- The core crate already depends on `serde`, `serde_json`, `toml` and `thiserror`, so this story adds no dependency and no `Cargo.lock` package.
- The built-in actions are embedded with `include_str!` from `actions/images.toml` and `actions/pdf.toml`; there are 45 actions and they must all still parse.
- The contract says `kind = "none"` requires no fields and no presets, so every new built-in options block that declares a field sets `kind = "form"`, not only `image.resize-50`.
- The acceptance tests in `crates/core/tests/s117_options.rs` are written from this contract by the tester and are not edited by the implementer.

## Acceptance criteria
- AC1 (module and public types): a new file `crates/core/src/options.rs`, declared as `pub mod options;` in `lib.rs`, defines exactly these public items, with all fields `pub` and the given derives: `OptionsKind { None, Form }` (kebab-case serde, `Default = None`); `Kind { Percent, Px, PxPair, Enum, Bool, Int, Float, String }` (kebab-case serde, `Copy`, `Eq`); `Choice { id, label }`; `Preset { id, values: toml::Table }` with `values` defaulted; `Field` with `id`, `kind` renamed to `"type"`, `label: Localized`, and the defaulted `default: Option<toml::Value>`, `min`, `max`, `step` (`Option<f64>`), `unit: Option<String>`, `values: Vec<Choice>`, `maps_to: Option<String>`, `clears: Vec<String>`, `no_enlarge: bool`; `OptionsSpec` with defaulted `kind`, `readout: Vec<String>`, `remember: bool`, `suffix_template: String`, `fields` (serde rename `"field"`), `presets` (serde rename `"preset"`), and `#[serde(deny_unknown_fields)]`; `OptionsError` as a `thiserror` enum with `Unknown(String)`, `Type { name, expected }`, `Value { name, reason }`. All types are `Clone, Debug, PartialEq, Serialize, Deserialize`; the two enums are also `Copy, Eq`. `Field::param_key()` returns `maps_to` when set, else `id`.
- AC2 (parsing): a TOML options document parses into `OptionsSpec` with `kind`, `readout`, `remember`, `suffix_template`, every field value (`default`, `min`, `max`, `step`, `unit`, `maps_to`, `clears`, `no_enlarge`), enum choices with labels, and preset values, unchanged. The same document parses as `[action.options]` on an action loaded through `Registry::add_toml`, and an unknown key inside the options table is a parse error.
- AC3 (`resolve`): starting from a clone of the base table, a value present in `explicit_fields` is validated, every key in the field's `clears` is removed from the output, and the value is inserted under `param_key()`; a field id and a param key both find the field, the field id first when a key could match both; a key that matches no field is `OptionsError::Unknown` with the key in the message and an untouched base is returned as `Err`. Keys not named by an explicit field stay in the output.
- AC4 (`resolve_params`): the same merge for a caller that names values by param key, preferring the param key match when a field id and a param key collide, and still accepting a field id. On the built-in `image.resize-50`, explicit `max_side` removes `scale` from the resolved table and explicit `scale` removes `max_side`.
- AC5 (no defaults applied): `resolve` and `resolve_params` with an empty explicit table return the base table unchanged; on the built-in `image.resize-50` an empty base plus an empty explicit table resolves to an empty table, so the field defaults (50 and 1920) are not inserted.
- AC6 (value validation): `Int`, `Percent` and `Px` accept a TOML integer only; `Float` accepts an integer or a float; `Bool` a boolean; `String` a string; `PxPair` a string matching `^[1-9][0-9]*x[1-9][0-9]*$` (so `0x10`, `1920X1080`, `1920x`, `x1080`, `1920x0` and `a` are refused); `Enum` a string that is one of the choice ids. With `min` or `max` set, an out of range value is `OptionsError::Value` whose text names the field and contains `below` or `above`; a wrong TOML type is `OptionsError::Type` whose text contains `expected`. Display strings are exactly ``unknown option `{0}` ``, ``option `{name}`: expected {expected}`` and ``option `{name}`: {reason}``.
- AC7 (JSON Schema): `params_schema()` returns `{"type":"object","properties":{...},"additionalProperties":false}`, property keys are param keys, and per kind: `int`, `percent` and `px` give `"integer"`; `float` gives `"number"`; `bool` gives `"boolean"`; `enum` gives `"string"` with `"enum"` of the choice ids in declaration order; `string` gives `"string"`; `px-pair` gives `"string"` with `"pattern"` equal to the validation regex. `minimum` and `maximum` come from `min`, `max`; `default` is the field default converted to JSON; `description` is the English label, plus `" (unit)"` when a unit is set. The export is a valid JSON Schema object with no non standard keys.
- AC8 (`OptionsSpec::validate`): accepts an empty spec and `kind = "none"` with no fields and no presets. Rejects: fields or presets with `kind` `none` or absent; a duplicate or empty field id; an enum with no values; an enum default that is not one of its values; a default whose type does not match its kind; a default outside `min`..`max`; `min > max`; two fields sharing a param key; a `clears` entry equal to the field's own param key; a preset key that is not a field id; a preset value that fails the field's value rules. A complete spec with one preset validates.
- AC9 (registry wiring): `ActionDef` gains `options: Option<OptionsSpec>` with `#[serde(default, skip_serializing_if = "Option::is_none")]`. `action_impl::validate` calls `options.validate()` and turns a failure into `RegistryError::Parse` whose message contains the action id, and the failed action is not added to the registry.
- AC10 (built-in actions): `Registry::builtin()` still has exactly 45 actions, all valid, and exactly these seven carry options, in this order: `image.to-webp`, `image.to-jpg`, `image.to-avif`, `image.resize-50`, `image.compress`, `pdf.compress`, `pdf.to-images`. Each of the four lossy image actions has a `form` spec with an integer `quality` field, `maps_to = "quality"`, `min = 1`, `max = 100`, `unit = "%"`, and `default` equal to the current `[action.params]` value (85, 90, 70, 75). `image.resize-50` has `kind = "form"`, `readout = ["dimensions", "ratio", "percent", "output_name"]`, `scale` (percent, min 1, max 1000, default 50, `maps_to = "scale"`, `clears = ["max_side"]`) and `max_side` (px, min 16, max 20000, default 1920, `maps_to = "max_side"`, `clears = ["scale"]`); its base params keep `scale = 50`. `pdf.compress` has an enum `preset` with ids screen, ebook, printer, prepress, default ebook, `maps_to = "preset"`. `pdf.to-images` has an integer `dpi` with min 72, max 600, default 150, `maps_to = "dpi"`. Every field label and every enum choice label has a non empty Arabic and English string. No other action gains options, and no action loses one.
- AC11 (scope and gates): no new dependency and no new `Cargo.lock` package; the workspace stays at Rust 1.85; `cargo fmt --check` and `cargo clippy -p kawaro-core --all-targets -D warnings` pass, and `cargo test -p kawaro-core` passes including the existing registry tests. No change under `crates/ui`, `crates/daemon`, `crates/cli` or `crates/engines`, no IPC change, no output naming change, and no change to `docs/architecture.md`, `docs/engines.md` or `CHANGELOG.md` in this block.
