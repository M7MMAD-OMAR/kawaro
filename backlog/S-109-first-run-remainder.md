# S-109 First run remainder: notification tri-state and the S-089 test map
Status: done (live Windows matrix and minimum width visual check are manual, not run)

## Story
As a Kawaro user, I want one notification choice with three clear options (Off, every finished job, only jobs that took 10 seconds or more), so I can control notifications without reading two switches. As the maintainer, I want every shipped S-089 criterion tied to a named existing test, so what is proven and what is not stays visible.

## Evidence and limits
- Today `Config` has two booleans, `notify` and `notify_long_only` (`crates/core/src/config.rs:83,86`). The settings page has two switches. The decision is the private `should_notify(enabled, long_only, Option<Duration>)` in `crates/daemon/src/jobs.rs:140`, with the 10 second rule and one test, `notification_policy_respects_duration_and_switch`, at 9 s and 10 s only (no 9.999 s case).
- Elapsed time comes from `JobEvent` (`TaskDone`, `TaskFailed`), so a fake clock is a plain `Duration` value. No sleeping, no real timer.
- Existing batch behaviour stays: one notice per finished or failed task, cancelled tasks give none (`batch_notices_follow_each_task_duration_and_policy`).
- Cannot be done by agents: the live Windows matrix run of S-089 (a person with a VM or machine). It is manual and not run. AC3 of S-089 (a real bundled video) is superseded, not met: S-094c replaced it with a live vector film, status done, shipped in 0.4.3 (`backlog/S-094c-introduction-film.md`, `CHANGELOG.md`, tests in `crates/ui/tests/s094c_film.rs`). No real video exists and none is planned.

## Acceptance criteria
- AC1: A pure function `notify_decision(mode, elapsed: Option<Duration>) -> bool` lives in `kawaro_core` with `NotifyMode { Off, All, Long }` and one constant `LONG_JOB = 10 s`. Off is false for every input. All is true for every input including `None`. Long is true only for `Some(d)` with `d >= 10 s`: `Some(9.999 s)` false, `Some(10 s)` true, `Some(0)` false, `None` false (documented fallback: unknown timing is silent). The daemon uses it in place of `should_notify`; the two booleans are no longer read there.
- AC2: Config stores `notify_mode = "off" | "all" | "long"`. Old files load with the same behaviour: (notify, notify_long_only) = (false,false) and (false,true) give Off; (true,false) gives All; (true,true) gives Long; a file with neither key gives All (today's default); a file with `notify_mode` ignores the two legacy keys. Saving writes `notify_mode` and also the two legacy keys derived from it (Off = false,false; All = true,false; Long = true,true), so a downgrade keeps the behaviour. An unknown `notify_mode` value falls back to All with a load warning and does not fail the load. Other keys round trip unchanged.
- AC3: The settings page replaces the two switches with one list of three options, same list style as theme and quality. Labels in English: "Notifications" (list), "Off", "Every finished job", "Only jobs that took 10 seconds or more". Arabic: "الإشعارات", "إيقاف", "كل عملية تنتهي", "فقط ما استغرق 10 ثوانٍ أو أكثر". Exactly one option is selected after load, matching the stored mode. Picking another marks the form as unsaved; Cancel restores the stored mode; Save writes it. The welcome window shows the same three options through the shared page. Every option has an accessible label equal to its visible text. No long dash in any string.
- AC4: Failures and batches are unchanged and pinned: with Long, a failed task that ran 12 s notifies and one that ran 3 s does not; a cancelled task never notifies in any mode; a batch of 4 tasks (1 s, 10 s, failed 12 s, cancelled 12 s) gives 0 notices in Off, 3 in All, 2 in Long. Notifications never take focus (existing `s049` tests stay green).
- AC5: The S-089 test map below is exact: a source test reads this file, takes every entry written as `path::test_name` in the map, and asserts the file exists and contains `fn test_name`. 0 missing entries. Criteria with no test are listed as "unmapped" with the reason, so nothing is claimed that no test shows.
- AC6: S-089 AC3 is recorded as superseded by S-094c with the evidence above; the live Windows run is recorded as manual and not run. No criterion is marked verified on Windows.
