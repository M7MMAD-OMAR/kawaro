# S-133 pdf.compress: no duplicate file when the result is not smaller
Status: in progress (this block, 2026-11-04; found by the real e2e run of 2026-11-04)

## Story
As a user, when a PDF is already compressed, I want `pdf.compress` to tell me there is no smaller result instead of writing a second file named `-compressed` that is byte identical to the original, so that I do not end up with a duplicate and a misleading name. The keep-smaller rule is right and stays: the engine never replaces a good original with a larger rewrite.

## Facts found while planning (code read, plus the e2e report)
- `crates/engines/src/pdf.rs` `GhostscriptEngine::compress` distils with `-sDEVICE=pdfwrite -dCompatibilityLevel=1.5 -dPDFSETTINGS=/preset` plus the DPI downsampling flags, then compares the input and output lengths with `keep_original(in_len, out_len)`. When the output is not smaller it runs `std::fs::copy(&input, &task.output)`, so the task reports a normal output and the queue finalises a byte-identical copy under the action suffix.
- The queue in `crates/core/src/queue_impl.rs` runs `Engine::run` and calls `finalize(&task.output, fin)` only for `Ok(())`; an `Err` is a `TaskFailed` and the temp file is removed. There is no neutral "finished, nothing to write" outcome today.
- The surfaces all key off `JobEvent::TaskDone` and `TaskFailed`: the CLI prints output paths and failures; the daemon notification is built in `crates/daemon/src/jobs.rs` from `JobInfo` (ok, failed, first output, first error); MCP collects outputs and errors in `crates/mcp/src/tools.rs` and returns `isError: true` only when a task failed; the UI surface is the notification and the tray count.
- The e2e report records `doc-copy.pdf` 162,904 bytes with preset `ebook` and `dpi = 100`: Ghostscript produced nothing smaller, the engine kept the original, and `out/s08-compress/doc-copy-compressed.pdf` is byte identical to the input; the same file at preset `screen` and `dpi = 72` gives 27,736 bytes. The report and `out/s08-compress` are under `/home/sbarah/kawaro-e2e`.
- The action itself is fine: `pdf.compress` is `ring = 1`, `order = 10`, per file, suffix `-compressed`, with the four presets and the `dpi` field 0 to 600 where 0 uses the preset. No action or option change is needed.

## Acceptance criteria
- AC1 (neutral skip outcome): the engine contract gains a third result next to success and failure. `Engine::run` returns `Result<TaskOutcome, EngineError>` where `TaskOutcome` is `Written` (the default for every existing engine) or `Skipped(SkipReason)`, a deliberate no-output result with a closed reason. `SkipReason` is a small serde enum in core with `AlreadyOptimized` (and room for later reasons); each surface formats it in its own language instead of carrying an English sentence in the event. `EngineError` stays for real failures, cancellations and bad parameters. The queue turns `Skipped` into a new `JobEvent::TaskSkipped { job, input, reason, elapsed }`, removes any temp file, does not count the task as ok or failed, and `JobEvent::Finished` gains `skipped: usize` with `#[serde(default)]` so the existing event shape keeps working. The IPC mirror of the event and the daemon `JobInfo` gain a skipped count and a first skipped reason.
- AC2 (engine rule): when the Ghostscript output is not smaller than the input, the engine returns `TaskOutcome::Skipped(SkipReason::AlreadyOptimized)`, writes no `task.output`, and leaves the temp file absent. When the output is smaller, it behaves exactly as today: it moves the smaller rewrite to `task.output` and returns `Written`. Equality counts as skipped, never as a copy. The original input bytes and timestamp are untouched, and no file with the `-compressed` suffix is created for a skipped task.
- AC3 (surfaces say already optimized): the CLI prints one line for a skipped task, for example `skipped: <input>: already optimized: the compressed result is not smaller, the original is kept`, on both the in-process and the daemon `--wait` paths, and exits 0 when the job had no real failure (a skip alone is not an error). The daemon notification for a job with only skipped tasks says the file is already optimized and no new file was written; a mixed job counts the skipped tasks separately and does not open the output folder for a skip. MCP returns `isError: false` with text that says no file was written and why, `structuredContent.outputs` empty and a `skipped: [{path, reason}]` list where `reason` is the enum serialized as `already-optimized`; no error code is invented. The stage 2 panel closes as it does for any Run and the notification is the UI result line.
- AC4 (tests): a fake Ghostscript program that writes a larger or equal output makes the engine return `Skipped` and the queue produce `TaskSkipped` with no final file and no temp file; a fake program that writes a smaller output returns `Written` with the output path. With a real Ghostscript when it exists, an already optimized PDF gives skip and a compressible PDF gives an output; the real test skips with a printed notice when `gs` is absent. The CLI line and exit code are tested, the daemon notification text is tested through the existing `captured_log` seam, the MCP skip shape is tested from a fake event stream, and a mixed run with one skipped and one written task keeps the written output and reports one skip.
- AC5 (no schema change, gates and changelog): the `pdf.compress` action, its suffix, presets and option schema do not change, and no new action is added. The keep-smaller rule is not weakened. `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, the tests of `kawaro-core`, `kawaro-engines`, `kawaro-daemon`, `kawaro-cli` and `kawaro-mcp` pass in the touched scope, no new dependency is added, and one bilingual `CHANGELOG.md` line names S-133 and the already-optimized message. No em dash or en dash in any changed file.
