## Story
As a visitor, I want a calm home page with one obvious download, a believable try-it demo and links that always work, so that I understand the product in seconds and never hit a dead link.

## Acceptance criteria
- AC1 (hero): in every built home page (`index.html`, `en/index.html`) the `.hero` contains exactly 1 `a.button-primary` (the download button), exactly 1 link with `href` ending `download/` (text "all downloads"), 1 beta notice as a single `<p class="hero-note">` (at most 90 characters, no `<a>` inside except the Windows link), and 0 `.pill`, 0 `.facts`, 0 links to `releases/download/`. The hero HTML is at most 1200 bytes outside the SVG. The primary button has `data-os-default="linux"`; `app.js` swaps its label and `href` to Windows when `navigator.userAgent` contains `Windows` and keeps Linux otherwise. With JS off the button shows a plain "Download" label that links to `download/`. In the screenshot matrix the bounding boxes of `.hero-copy` children and the hive `<svg>` do not intersect (0 px overlap).
- AC2 (spacing system): `design/tokens.json` gains `space-7` and `space-8` (48 and 64 px) and `scripts/tokens-to-css.py` emits them. In `site/style.css` every `margin`, `padding`, `gap`, `row-gap`, `column-gap` and `inset` value is `0`, `auto`, a `calc()` of only `var(--space-*)`, or `var(--space-*)`; 0 hand-written `px`, `rem` or `em` in those properties (selectors in `@media` included). Every `section.sec` has the same vertical padding `var(--space-8)` at 1280 px and `var(--space-7)` at 375 px. Every `.wrap` has the same max width and inline padding of `var(--space-4)` at 375 px. Header items have a measured gap of exactly 8 px (`--space-2`) at 1280 px.
- AC3 (top bar): at 375, 768 and 1280 px the header has 0 horizontally overflowing children (`scrollWidth <= clientWidth`), no two header links overlap (0 px), and the support button is in the header exactly once. The header height is the same on every page in one language (difference 0 px).
- AC4 (mouse effect): `app.js` has 0 `pointermove` or `mousemove` listeners outside the simulation, and `style.css` has no custom property fed by pointer position. Any hover effect left changes only `background` to a `--color-surface-*` token over at most `var(--motion-hover)`.
- AC5 (support): every support link in `site/**/*.html`, `README.md`, `README.ar.md` has an `href` equal to `https://sbarah.com/support` (string equality, no query). On the site each also has `target="_blank"` and `rel="noopener noreferrer"`. The site has 0 files under a path containing `support`. Header, footer and the support section each hold one such link (6 per language pair counted across `index` and one inner page is the check target: header 1, footer 1, section 1 per page that has it). The support section (`#support`) contains exactly 1 `<a>` and no other button, and that link wraps a `<picture>` using `docs/assets/support-sbarah-dark.svg` for dark and `-light.svg` for light, copied to `site/assets/` by the build. The section pins a Sbarah theme from new tokens `sbarah.*` in `design/tokens.json` (colours read from the two SVG files: dark `#161616`, accent `#BBD686`, heart `#B2675E`, text `#FDFBF7`; the light values from the light SVG), and the section has 0 `--color-*` references to the site palette. The two SVGs are the owner's assets, shown as images and exempt from the shadow rule.
- AC6 (downloads never dead): `build.py` reads `RELEASE_PUBLISHED` from the environment (default `0`). At `0`, every download button on every page links to `https://github.com/M7MMAD-OMAR/kawaro/releases`, Windows and the beta show a "coming soon" label (`soon` / "قريبا") and the built site has 0 occurrences of `/releases/download/`. At `1`, buttons link to the asset URLs in `FILES`, and the build exits 1 with a message if `git tag -l v<VERSION>` prints nothing. `scripts/site/check-deploy.sh` gets a `--links` step: it extracts every `releases/download/` URL from the built site and from `README*.md`, and exits 1 and prints the URL on an HTTP 404 (or on a tag missing locally when offline).
- AC7 (simulation, behaviour): the home page has a `#sim` section with a drop zone, 5 sample files (`clip.mov`, `photo.png`, `report.docx`, `song.wav`, two PDFs) and a hive area. Dragging `clip.mov` onto the zone (or choosing it and pressing Enter or Space) shows the hive within 150 ms with exactly the cells of the video kind from `build.py` (10 cells, the first labelled MP4, centre cell text "One video"). Picking a cell (click or Enter) shows a result row in the same folder list: `clip.mp4` for MP4, listed after `clip.mov`, with `clip.mov` marked "Original, untouched". Escape closes the hive and returns focus to the sample file. Each file kind shows its own cells (image 12, video 10, document 2, audio 4, two PDFs 5). The simulation makes 0 network requests (checked by the CSP run of S-059 AC3 and by a Playwright request count of 0 after load).
- AC8 (simulation, access): the zone, each sample and each hive cell is reachable by Tab, has an accessible name, and a visible focus ring of `var(--border-focus)`. With `prefers-reduced-motion: reduce` there is no CSS animation or transition longer than 0 ms in `#sim` and the result appears at once. `#stage-live` announces the result file name. The section works with JS off as a static picture plus the text "turn on JavaScript to try it".
- AC9 (RTL and footer): in `/` (ar) all flex and grid order mirrors (the brand is at the right edge, the language switch at the left edge in a 1280 px screenshot), 0 uses of `left`, `right`, `margin-left`, `margin-right`, `padding-left`, `padding-right`, `text-align: left|right` in `style.css` (logical properties only). Latin tokens inside Arabic text (`MSI`, `DEB`, versions) are wrapped in `<bdi>` or `dir="ltr"`. Footer links form two groups per language: the product group, then the language switch. In the Arabic page every footer link text has 0 Latin letters except `GitHub`, `SHA256SUMS`, and file codes; in the English page 0 Arabic letters except the language switch "العربية". The footer is a `<ul>` list, not a text line joined by `·`.
- AC10 (contrast): for every text and background pair in `style.css` (light, dark, `.inv`, Sbarah section, button states) the contrast ratio computed by a test script is at least 4.5 (3.0 for text of 24 px or more and for UI borders). The test prints the pair list and fails with the lowest ratio.
- AC11 (mobile): at 375 px the page has 0 horizontal scroll (`documentElement.scrollWidth <= 375`), every tap target is at least 44 by 44 px, body text is at least 16 px, and the hero primary button is fully visible without scrolling at 375 by 667.
- AC12 (finish): no `site/**/*.html` or `style.css` change breaks S-059 AC3 (inline script hashes, no `on*=`, `style=` only `--name:number`), `scripts/design-lint.sh` gives 0 matches, a long dash search over the diff gives 0 matches, `CHANGELOG.md` has one new line in English and Arabic for S-061, and the build is reproducible (two runs give identical files, `diff -r` empty).
