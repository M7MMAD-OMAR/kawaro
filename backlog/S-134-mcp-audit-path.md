# S-134 MCP audit_path: make the config key real, with rotation
Status: in progress (this block, 2026-11-04; found by the real e2e run of 2026-11-04)

## Story
As a user or administrator, I want to choose where the MCP audit log lives with `[mcp] audit_path`, so that the record of what a model asked this machine to do can go to a state folder, a mounted log, or a per-project location instead of always landing in the Kawaro config folder. The key exists in the struct today but is not read from TOML, so the documented and actual behaviour disagree.

## Facts found while planning (code read, plus the e2e report)
- `crates/mcp/src/config.rs` has `pub audit_path: Option<PathBuf>` and its own comment says it is "not read from the TOML: it is a seam for the tests". `from_table` reads `enabled`, `read_only`, `allowed_roots`, `max_files`, `audit` and `preview_px` only. `Default` leaves `audit_path` as `None`.
- `crates/mcp/src/audit.rs` `audit_file` returns `config.audit_path` when set (the test seam) and otherwise `kawaro_core::paths::config_dir()` joined with `mcp-audit.jsonl`. Rotation to `.1` above 1 MiB and parent directory creation already work for whichever path is chosen.
- `docs/mcp.md` and `docs/mcp.ar.md` both say the audit file is `mcp-audit.jsonl` in the Kawaro config folder and "stays there even when --config points somewhere else"; neither mentions an `audit_path` key. The e2e report records the same: the brief asked for `audit_path`, the code did not read it, and the file landed at `config/kawaro/mcp-audit.jsonl`.
- The existing MCP tests set `Config { audit_path: Some(temp path), .. }` directly, so the field is a live seam in tests; the config file test asserts `audit_path` is `None` when the key is absent. A new key must keep those tests meaningful and add file parsing coverage.
- ADR 0011 decision 6 sets the default audit path to `<config dir>/mcp-audit.jsonl` with rotation; an explicit user override does not contradict the default, so no new ADR is needed for this story.

## Acceptance criteria
- AC1 (the key is read and resolved): `Config::from_table` reads `[mcp] audit_path` as a string, sets `Config.audit_path` to `Some(PathBuf)`, and leaves it `None` when the key is absent, empty or not a string. A new `Config::resolved_audit_path()` returns the path the audit will use: the default `<config dir>/mcp-audit.jsonl` when the field is `None`, an absolute value as written, `~` and `~/...` expanded with `HOME`, and a relative value resolved against the Kawaro config directory (documented). The file does not need to exist yet; the parent is created by the writer. The public field remains the seam for tests, and `from_file` keeps returning the default plus warning for an unreadable or broken file.
- AC2 (writer behaviour and rotation): `audit.rs` uses `resolved_audit_path()` instead of its own default branch. With `audit = true`, every `tools/call` appends one JSON line to that path, creating missing parents, and the 1 MiB rotation renames the file to `.1` and starts a fresh file at the same path. With `audit = false` no file is created or written. A write failure stays silent, as today, and never fails a conversion. Two calls produce two lines; a rotation produces one line in the new file and the old bytes in `.1`.
- AC3 (docs aligned, both languages): `docs/mcp.md` and `docs/mcp.ar.md` show `audit_path` in the `[mcp]` example and explain: the default is `<config dir>/mcp-audit.jsonl`, an absolute path or `~/...` is recommended, a relative path is resolved against the Kawaro config directory, rotation is at 1 MiB to `.1`, and the old sentence that the file always stays in the config folder regardless of `--config` is replaced by the real rule. The two language files say the same thing and neither contains a long dash.
- AC4 (tests): parsing tests cover an absolute path, a `~` path and a relative path in the table, the absent and wrong type cases, and the empty string; a pure resolution table covers `HOME` set and unset for `~` and `~/...`, absolute and relative; writer tests cover two lines at a custom path, parent creation, rotation at a custom path, `audit = false`, and the unchanged default path when the key is absent. The existing `audit_path` seam tests keep passing with no edits other than the ones the tester owns.
- AC5 (gates and changelog): no new dependency and no `Cargo.lock` package; `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test -p kawaro-mcp` and `cargo test -p kawaro-core` pass in the touched scope; one bilingual `CHANGELOG.md` line under Unreleased names S-134 and the configurable audit path; no em dash or en dash in any changed file. The e2e observation that a test daemon registered GlobalShortcuts with the live session portal is a test isolation issue and is not part of this story.

## Out of scope
A new audit format or fields, a JSON schema for the audit line, log rotation by date or count beyond the single `.1`, logging tool arguments or file contents, a settings UI control for the path, an environment variable override, per-tool audit switches, moving the audit out of the MCP process, and any change to the default when the key is absent. The test daemon GlobalShortcuts registration on the live portal is out of scope; it is a test isolation gap (start the test daemon with the portal and tray disabled) and should get its own story if the Lead wants one.
