# S-112 AppStream metadata, one install command source, signed checksums
Status: approved (2026-10-31, manager)

## Story
As a Linux app store user I want Kawaro to show its icon, a real screenshot and bilingual release notes, and as a user of any channel I want every install command in the docs to be the same text, so that nothing I copy is stale. This is the account free part of S-078a, S-016 decision 8 and S-016e. Needs no account and no network; fast loop only.

## Facts found while planning
- `README.md`, `README.ar.md`, `docs/guide/install.md` and `install.ar.md` carry no apt, copr, aur or winget command today. Commands live in `docs/distribution.md`, `distribution.ar.md` (table) and `docs/distribution-channels/{apt,copr,aur}.md`. `docs/distribution-channels/aur.md` has a damaged code block (stray text before `yay -S kawaro-bin`); `copr.md` says `OWNER/kawaro` while the tables say `ACCOUNT/kawaro`.
- `tests/release/install_commands.sh` and `packaging/install-commands.json` do not exist. The live AUR package is `kawaro-bin` (S-103e), so S-078's source `kawaro` PKGBUILD text is superseded.
- No release attaches `SHA256SUMS.asc` or `kawaro-archive.asc`: `packages.yml` job `release` uploads only the four assets and `SHA256SUMS`. The key `APT_SIGNING_KEY` lives in environment `apt-publishing`.
- Real hive renders exist: `crates/ui/tests/snapshots/hive-en-light.png` and `hive-ar-dark.png` (checked by opening them: only action cells, no personal data). No tracked desktop screenshot of the hive exists; a captured one is remaining work.

## Acceptance criteria
- AC1 icon: the metainfo declares exactly one `<icon type="stock">kawaro</icon>`, and the files `design/brand/kawaro.svg` and `design/brand/png/kawaro-128.png` exist and `packaging/linux/stage.sh` installs them as `apps/kawaro.svg` and `apps/kawaro.png`.
- AC2 screenshots: exactly 2 `<screenshot>` elements, the first `type="default"`. Each has an English `<caption>` and a `<caption xml:lang="ar">` (non empty, the Arabic one contains Arabic letters), and one `<image type="source">` whose `width` and `height` equal the PNG header values of the copied file and whose URL is `https://kawaro.sbarah.com/screenshots/<file>`. Files: copies of `hive-en-light.png` and `hive-ar-dark.png` in `packaging/screenshots/`, byte identical copies in `site/screenshots/`, and both installed by `stage.sh`, `packaging/linux/kawaro.spec` and `packaging/copr/kawaro.spec` under `/usr/share/kawaro/screenshots/` (the existing spec file list test still passes).
- AC3 releases: every `<release>` entry (17 today) has an English `<p>` and a `<p xml:lang="ar">` in `<description>`; the Arabic text has Arabic letters, Western digits and no long dash. Adding a release without Arabic fails the test, so the check guards future releases.
- AC4 validation: when `appstreamcli` exists, `appstreamcli validate --pedantic --no-net` on the metainfo exits 0; otherwise the test prints `SKIP S-112 appstreamcli is not installed` and the XML parse checks (AC1 to AC3) still run. Live screenshot URL checks are remaining work.
- AC5 one source: `packaging/install-commands.json` has `schema: 1` and channels `apt`, `copr`, `aur`, `winget`, each with `status` and `commands` (list of strings): apt `live`; winget `submitted` (PR waits for review); copr `not_live`; aur `not_live` (`yay -S kawaro-bin`; copr uses `ACCOUNT/kawaro`). `scripts/release/install-commands.py` prints a channel's commands (`render NAME`) and exits 1 when a docs file lacks any of them (`check`).
- AC6 docs match: `check` passes on `distribution.md`, `distribution.ar.md` and `distribution-channels/{apt,copr,aur}.md`, which this story aligns (fix the `aur.md` block, `OWNER` to `ACCOUNT`, drop the sentences saying the JSON does not exist). A channel with `not_live` must say `Not usable yet` in `distribution.md` and `غير قابل للاستعمال بعد` in the Arabic page; `live` must not. Any line in README, README.ar.md and both install guides that starts a channel command (`yay -S`, `dnf copr enable`, `winget install`, `/etc/apt/keyrings`) must be one of the JSON commands.
- AC7 signed checksums: `scripts/release/sign-checksums.sh` plus a `packages.yml` job `sign-checksums` (needs `release`, `if` tag `v*` and `github.repository == 'M7MMAD-OMAR/kawaro'`, `environment: apt-publishing`) that prints `SKIP sign-checksums: APT_SIGNING_KEY not configured` and exits 0 when the secret is empty; otherwise imports the key into a `mktemp -d` GNUPGHOME (mode 0700, removed by an `EXIT` trap), refuses a fingerprint different from `packaging/keys/kawaro-archive.asc`, signs `SHA256SUMS` as armored `SHA256SUMS.asc`, and uploads it and `kawaro-archive.asc` with `--clobber`. The `release` job still uploads exactly 4 assets plus `SHA256SUMS` and the `wc -l` check stays 4. Never run locally.
- AC8 finish: one `CHANGELOG.md` line `English | العربية`; no long dash in any changed file; `bash -n` and shellcheck (when installed) pass on new scripts; `scripts/design-lint.sh` passes; `tests/release/run_all.sh` lists the 3 new tests.
