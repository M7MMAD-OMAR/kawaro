# S-121 MCP read-only server: formats and plan over stdio
Status: done (2026-11-04)

## Story
As a user of a local AI host, I want Kawaro to answer what it can do and what it would do with my files, with no write and no network, so that an agent can plan before it is allowed to convert anything. This is the first slice of ADR 0011: the server, the config, the discovery surface, the two read tools, the refusal gates, the audit line and the CLI entry. The four write tools are declared in this slice and executed in S-122.

## Facts found while planning
- The MCP crate does not exist yet. The workspace has five crates and no async runtime; `rmcp` needs Rust 1.88 and tokio, so the loop is hand written (ADR 0011, decision 2).
- `Registry::builtin()` returns the 45 shipped actions, `Registry::matching(files, engine_ok)` answers which fit a selection, `queue::plan(action, files)` returns the final output paths without writing, and `kawaro_engines::all()` gives every engine with `id()` and `available()`.
- `kawaro_core::config::Config::path()` gives `config.toml` under the platform config folder; the `[mcp]` table is new and is read by the MCP crate, not by the daemon's config model.
- The base64 and image crates are already in `Cargo.lock` through other crates; the server itself adds no locked package.
- The acceptance tests for both MCP stories are in `crates/mcp/tests/s121_mcp.rs`, written by the tester from the contract, not edited by the implementer.

## Acceptance criteria
- AC1 (crate and wiring): new crate `crates/mcp`, package `kawaro-mcp`, lib name `kawaro_mcp`, with `Config` and `serve` public. The workspace `members` list gains `crates/mcp` and `[workspace.dependencies]` gains `kawaro-mcp`; `crates/cli/Cargo.toml` gains `kawaro-mcp.workspace = true`. The crate uses no `rmcp`, no tokio, no HTTP or network crate, and the workspace `rust-version` stays `1.85`. `Cargo.lock` gains no `[[package]]` entry (base64 0.23.1 and image 0.25.10 are already there, and a workspace path member is not a lock entry). `image` is a dependency for the preview and also a dev dependency with the `png` and `jpeg` features for the tests.
- AC2 (`Config`): `Config { enabled, read_only, allowed_roots, max_files, audit, preview_px, audit_path }` with `Default` = false, true, empty, 50, true, 512, `None`. `from_table(&toml::Table)` reads `t["mcp"]` keys `enabled`, `read_only`, `allowed_roots`, `max_files`, `audit`, `preview_px`; a missing or unknown key falls back to the default and `audit_path` is not read. `from_file(path)` returns `(Self, Option<String>)` and gives a warning string for an unreadable or unparsable file instead of failing. `default_path()` is `kawaro_core::config::Config::path()`. `resolved_roots()` expands a leading `~` with `HOME`, makes a relative path absolute, canonicalises every entry and keeps only existing directories, preserving order.
- AC3 (disabled): `serve` with `enabled = false` returns `Err(io::Error::other("MCP server is disabled: set [mcp] enabled = true in config.toml"))` and writes nothing to stdout. `run_stdio` returns that error as a `String`; the CLI prints it as `kawaro: {e}` and exits non zero.
- AC4 (transport loop): newline delimited JSON-RPC 2.0 in and out, at most one response line per request, flushed after each response. A request without `id` is a notification and gets no response; `notifications/initialized` and `notifications/cancelled` are ignored. `ping` returns an empty object result. An unknown method returns `{"code":-32601,"message":"method not found"}` with the request id. A malformed line returns `{"code":-32700}` with `"id": null` present. Only JSON-RPC lines reach stdout; every log line goes to stderr.
- AC5 (discovery): a legacy `initialize` request answers `{"protocolVersion":V,"capabilities":{"tools":{}},"serverInfo":{"name":"kawaro","version":env!("CARGO_PKG_VERSION")},"instructions":"Local file conversion and PDF tools. Nothing leaves the machine."}` where V is the requested version when it is 2026-07-28, 2025-11-25, 2025-06-18, 2025-03-26 or 2024-11-05, and 2025-11-25 otherwise. `server/discover` answers `{"resultType":"complete","protocolVersions":["2026-07-28","2025-11-25","2025-06-18"],"capabilities":{"tools":{}},"serverInfo":{...},"instructions":...}`. The only capability declared is `tools`; there are no resources and no prompts. The client name is taken from `initialize` `params.clientInfo.name` or from `_meta["io.modelcontextprotocol/clientInfo"].name` on a request, and is used in the audit line only.
- AC6 (`tools/list`): one result with `resultType` `complete`, `ttlMs` 300000, `cacheScope` `private` and exactly six tools in this order: `kawaro_formats`, `kawaro_plan`, `kawaro_convert`, `kawaro_images_to_pdf`, `kawaro_pdf`, `kawaro_image`. The list is byte identical across calls. Each tool has a `name`, a `description`, an `inputSchema` of type object with `paths` as an array of strings where a path is taken, `kawaro_pdf` and `kawaro_image` an `op` enum, and `options` as an object where options exist. No tool declares an `outputSchema` in this block.
- AC7 (`kawaro_formats`): arguments `{}`; text block plus `structuredContent` with `version` (crate version), `protocolVersions` (the three of `server/discover`), `engines` as `[{id, available}]` for every engine in `kawaro_engines::all()`, and `actions` as `[{id, engine, ring, label, has_options}]` for every action in `Registry::builtin()` (plus the user actions directory when it exists), with `label` the English label and `has_options` true only for an action with a spec. `isError` false.
- AC8 (`kawaro_plan`): arguments `{paths: [string]}`; no writes at all. The registry is `Registry::builtin()` plus the user actions directory when it exists; engine availability comes from `kawaro_engines::all()`. For each action that `Registry::matching` returns for the selection, `structuredContent.actions` has `id`, `ring`, `label` (English), `engine`, `options` (the action's `params_schema()`, or null), and `outputs` as the absolute final paths from `kawaro_core::queue::plan(action, &files)`. A text summary is present. No output file is created and the directory listing is unchanged.
- AC9 (path policy and limits): every requested path is made absolute, canonicalised, must be an existing regular file and must start with one of `config.resolved_roots()`, otherwise the tool fails with code `OUTSIDE_ROOTS`; an empty root list refuses every path. A selection longer than `max_files` fails with `TOO_MANY_FILES`. A path that does not exist or is a directory fails with `OUTSIDE_ROOTS` as well in this block. The failure is an `isError: true` result with the text `ERROR [CODE]: message` and `structuredContent.error {code, message}`, never a JSON-RPC error.
- AC10 (read-only gate): with `read_only = true` (the default) `kawaro_formats` and `kawaro_plan` work, and every one of the four write tools returns `READ_ONLY` with no engine built and no file written. Read-only is checked before argument parsing that would run an engine. This slice does not run write tools even when `read_only = false`; S-122 is the story that executes them.
- AC11 (audit): when `config.audit` is true, one JSON line is appended per `tools/call` (not per `initialize`, `ping`, `tools/list` or `server/discover`) to `config.audit_path` when set, else `<config dir>/mcp-audit.jsonl`; the directory is created. The line is an object with `ts` (unix seconds), `tool`, `ok`, `paths` (array), `outputs` (array), `client` (the captured client name, or an empty string when none) and `ms` (number). When the file is over 1 MiB it is renamed to `mcp-audit.jsonl.1` before the new line is written. `audit = false` writes no line and creates no file.
- AC12 (CLI): `kawaro mcp` starts `kawaro_mcp::run_stdio(config)`; `--config PATH` uses that file. A failure is printed with the existing `kawaro: {e}` path and a non zero exit. `--snippet claude`, `--snippet cursor`, `--snippet lm-studio` and `--snippet generic` each print exactly one line `{"mcpServers":{"kawaro":{"command":"kawaro","args":["mcp"]}}}` to stdout and exit 0, even with the server disabled. An unknown host is an error that lists the four accepted names.
- AC13 (explicit exclusions): methods outside discovery, `ping`, `tools/list` and `tools/call` return `-32601`, including `tasks/get`, `resources/list` and `prompts/list`. No HTTP code and no listening socket exist. No result carries `input_required`, no server initiated request is sent, and no `resources` or `prompts` capability is declared.

The daemon as executor (a later story after S-120). Docs, `docs/architecture.md`, `docs/engines.md` and `CHANGELOG.md` changes, which the Lead keeps outside this block.
