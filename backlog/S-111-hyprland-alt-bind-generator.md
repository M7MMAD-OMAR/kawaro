# S-111 Hyprland Alt bind generator, repair command and doctor drop-key states
Status: done (nested Hyprland harness run and a live session check are manual, not run; KDE and GNOME stay in S-075b)

## Story
As a Hyprland user who installed the package, I want Kawaro to write, repair and report the Alt drag bind for me, so that Alt then drag works without hand edited binds and a stale or foreign bind is never silent.

This is the agent-finishable part of S-075 (the triage calls it S-075a and S-075f). The bind shipped by hand in S-095, S-102 and S-104 becomes generated text; AC5, AC6, AC8 and AC7 of S-075 are covered here for Hyprland only. Evidence base: the S-104 measurements on Hyprland 0.57 (press bind with `--at`, non consuming release bind, Lua key hook for chords).

## Scope notes
- Command: `kawaro doctor --repair` (Hyprland only; elsewhere it prints `repair: not a Hyprland session` and exits 0). Hyprland config is read and written only through a Kawaro owned file `kawaro.lua` (or `kawaro.conf` for hyprlang) in the user's Hyprland config directory, which the user sources once; the user's own config files are never edited.
- Marked block: the generated file holds one block between the lines `-- kawaro:begin` and `-- kawaro:end` (`# kawaro:begin` and `# kawaro:end` in hyprlang). Everything outside the markers is user text and is preserved byte for byte.
- The drop key is a parameter (default `Alt`, S-076b will feed it later); this story adds no `drop_key` config field.
- Contracts fixed by the tester (names the tests call): module `kawaro_core::hyprland_bind` with `Syntax::{Lua, Hyprlang}`, `hyprland_bind_text(key, syntax, kawaro_path) -> String` (the text includes both marker lines and ends with a newline), `normalise_binary(path) -> String`, `merge_block(existing, block) -> Result<String, MergeError>`, `stale_launchers(local, installed) -> LauncherPlan { remove, keep }`, `drop_key_state(&StateInput) -> Option<State>`, `state_text(&State) -> String` (English value), and the message table `message_keys(Lang) -> Vec<&'static str>` plus `message(Lang, key) -> &'static str`.
- Repair environment: a session is Hyprland when `HYPRLAND_INSTANCE_SIGNATURE` is set. The config directory is `$XDG_CONFIG_HOME/hypr` (else `$HOME/.config/hypr`); the syntax is Lua when `hyprland.lua` exists there, hyprlang otherwise, and the file is `kawaro.lua` or `kawaro.conf`. Foreign and owned binds are read from `hyprctl binds -j`; the repair applies the change with one `hyprctl reload`.
- Binary path in generated text: the command name found through `PATH`, or `/usr/bin/kawaro`; never a path containing `.local`.

## Acceptance criteria
- AC1 (bind text, pure): `hyprland_bind_text(key, syntax, kawaro_path)` returns, for key `Alt` and for `Super+Z`, in both Lua and hyprlang: the non consuming press bind with `--at "$(hyprctl cursorpos)"`, the non consuming ignore-mods release bind, and, for Alt in Lua only, the chord key hook of S-102. Output equals a checked-in golden text for 4 cases (Alt Lua, Alt hyprlang, Super+Z Lua, Super+Z hyprlang); the hyprlang Alt text has 2 bind lines and 0 hook lines.
- AC2 (no `.local`): for 4 binary path inputs (`/usr/bin/kawaro`, `kawaro`, `/home/u/.local/bin/kawaro`, empty) the generated text contains 0 occurrences of `.local` and 0 occurrences of `$HOME`; the `.local` input maps to `kawaro` and the empty input maps to `/usr/bin/kawaro`.
- AC3 (idempotent merge, pure): `merge_block(existing, block)` on 6 inputs returns text where (a) no existing block: the block is appended once; (b) an existing equal block: output equals input; (c) a stale block: only the lines between the markers change; (d) markers with text above and below: those lines are byte identical; (e) a begin marker without an end marker: returns an error and the input unchanged; (f) two blocks: error, input unchanged. Applying merge twice equals applying it once for all 6 inputs.
- AC4 (stale launcher): `stale_launchers(dir_listing)` flags `kawaro` and `kawarod` files in `~/.local/bin` (a neutral path in tests: `<tmp>/home/.local/bin`) only when a binary named the same exists at `/usr/bin` or on `PATH` outside that directory; the repair removes exactly those files and prints one line per file. A user file `kawaro-notes.txt` in the same directory is never removed. A launcher with no installed counterpart is kept and reported as `keep: no installed kawaro found`.
- AC5 (repair, stub hyprctl): with a stub `hyprctl` first on `PATH`, `kawaro doctor --repair` run in a temp config directory: (a) no file yet: creates the file, prints `repair: wrote 1 block`; (b) a file with a stale block (binds pointing to a `.local/bin` binary): rewrites the block, prints `repair: updated 1 block`, the file has 0 `.local` matches; (c) a current file: prints `repair: nothing to do` and the file mtime is unchanged; (d) the user's own bind on the same key outside the block: the file is not touched, the command prints `conflict: Alt taken` and exits 1. The stub logs its calls; the test asserts the stub received `reload` exactly once in (a) and (b), and 0 times in (c) and (d).
- AC6 (doctor state, pure): `drop_key_state(input) -> State` with the four states `native Alt active`, `fallback <key> active`, `conflict: <key> taken`, `unavailable (denied)`. Table test over 10 rows of (bind state, foreign bind on key, portal denied flag, portal fallback registered): owned bind present gives `native Alt active`; foreign bind on the key gives `conflict: Alt taken` even if an owned bind exists; denied flag gives `unavailable (denied)` when no native bind; portal fallback registered with Super+Z gives `fallback Super+Z active` (verification note in the log: the evidence of a fallback is a `hyprctl binds -j` entry with dispatcher `global` and an argument ending `:drop`, key read from its modmask and key, never a daemon status); bind state unknown with no other signal gives no state line (the S-102 `unknown` line stays). Precedence is conflict, then native, then fallback, then denied; one row per precedence pair.
- AC7 (doctor output): `kawaro doctor` prints exactly one line starting `drop key state:` when a state exists, 0 such lines otherwise; the existing S-102 `drop key:` line is unchanged (its tests still pass). With the stub `hyprctl` returning bind JSON for each of the four states, stdout contains the exact four lines `drop key state: native Alt active`, `drop key state: fallback Super+Z active`, `drop key state: conflict: Alt taken`, `drop key state: unavailable (denied)`.
- AC8 (English and Arabic parity): the doctor states, the repair messages of AC5 and the stale launcher lines come from one message table with an English and an Arabic string per key. A test asserts both languages have the same key set (0 missing), no Arabic string contains `.local` or a long dash, and the Arabic doctor output for the four states equals golden text containing the key name unchanged (`Alt`, `Super+Z`) and Western digits only.
- AC9 (docs): `integrations/linux/hyprland/README.md` and `README.ar.md` replace the hand written `~/.local/bin` bind with `kawaro doctor --repair` and the one `source` line; a grep test finds 0 `.local/bin` binds in both files outside the section about the helper script. The two files keep the language switch line.
- AC10: one `CHANGELOG.md` line in English and Arabic; `cargo fmt --check`, clippy with `-D warnings` and tests of the touched crates pass; no long dash in any changed file.
