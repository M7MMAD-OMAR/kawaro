# S-130 The first-run language screen: the choice disappears on save and the screen fits the window
Status: implemented locally in 08976a1; language-choice snapshots covered, not yet a public release

## Story
As a first-run user, I want to pick Arabic or English on a calm, centred screen, and I want that screen to disappear as soon as the choice is saved so the introduction opens in my language, so that the first minute of Kawaro is not a stuck, stretched button page. The owner saw the language choice stay on screen after choosing, with two giant orange pills stretched to the bottom of the window, a hardcoded title, no RTL mirroring, and a language switch that did not reach the visible window.

## Facts found while planning (code read, no code changed)
- The language overlay is `crates/ui/ui/welcome.slint` lines about 237 to 277: a `FocusScope` filling the window, a `VerticalLayout` with `padding: Tokens.space-6` and `spacing: Tokens.space-4`, one hardcoded bilingual title, a hardcoded bilingual failure line, and a `HorizontalLayout` holding two `FilledButton`s with no width or height constraints. The horizontal layout takes the remaining height, so both buttons stretch into full height pills. There is no `root.rtl` branch in this block, unlike the rest of the file.
- The state is in `crates/ui/src/welcome.rs`: `WelcomeWindow::new(lang)` fixes the window language and sets `ui.set_rtl`; the comment records that a language change applies the next time the daemon creates the window. `choose_language()` sets a cell and the Slint property; `language_reload_failed()` only sets `language-save-failed`. `open()` calls `Inner::close`, builds a fresh UI in the window's own language, and shows it.
- The daemon path is `crates/daemon/src/ui.rs`: `on_language` saves with `save_language_choice` (returns false on a write error and keeps the choice), sets the tray language, then a zero delay `slint::Timer::single_shot` calls `build(lang, theme, &state, &queue)` and `present_welcome(&state)`. `build` clears the `WELCOME` slot and replaces `WELCOME_ARGS` with the new language. `present_welcome` calls `welcome_window()` (which creates a window only when the slot is empty), then calls `win.open(...)` only when `!win.is_visible()`, otherwise it only applies the theme and raises.
- Verified nuance: the code intends `build` + an empty slot to create a new welcome window, but nothing closes or hides the old window explicitly, `present_welcome` has no branch that replaces a still visible old window, the window language is fixed at creation, and no test asserts that the language overlay disappears after a successful save. This is the gap the story closes.
- The welcome snapshot harness is `crates/ui/tests/welcome_snapshots.sh` with `crates/ui/examples/welcome_snapshot.rs` (`--lang`, `--compare`, `--page`, `--size`, `--frame`, `--at-pointer`), four references `welcome-{en,ar}-{dark,light}.png`, a private headless KWin, and `--update` for rewriting references. There is no `--choose-language` yet.
- The visible strings currently come from Rust for the introduction (`kawaro_core::welcome::strings`), but the language screen hardcodes its title and error line in the Slint file.

## Acceptance criteria
- AC1 (successful save replaces the screen and the window): when a language is saved successfully, the daemon hides and closes the visible welcome window before presenting anything else, then builds a new welcome window with the saved `Lang`, `choose_language` false, and the introduction captions and strings in that language, in the same session. After the transition there is exactly one visible welcome window, no language overlay, no old language window on screen, and `welcome_seen` is still false. A failed save keeps the current window visible, keeps `choose_language` true, shows the failure line, and builds no new window. A successful save followed by a failed rebuild (the build returning an error) hides the old window and leaves no stale language overlay visible, and the failure is reported once on stderr.
- AC2 (design: a centred card, not stretched pills): the language screen is a centred content card inside the existing welcome window, which does not resize or move. The card uses `surface-0` or `surface-1` from the tokens, a full 1 px `border`, `radius-lg`, and `space-6` inner padding; it holds a title, a subtitle, the failure line when needed, and the two language options. Each option is a constrained button or card with an explicit height and a maximum width from design tokens (the proposal is `layout.language-option-height = 56` and `layout.language-option-width = 320`, with `layout.language-card-width = 520`), never a share of the remaining height. The two options fit at the minimum window width (560), and the card is centred horizontally and vertically. There is no shadow, no gradient, no one sided border, and every colour, length and radius is a token.
- AC3 (strings, RTL and keyboard): every visible string of the language screen comes from Rust in the window language: title, subtitle, failure line, the two option labels and their accessible labels, through new fields on `kawaro_core::welcome::Strings` (Arabic and English). The Arabic build mirrors the card contents and the option order by hand, aligns text to the right, keeps Latin digits in their own run, and the two language names stay correctly shaped. Tab moves between the two options, Enter or Space selects the focused one, Escape closes the welcome window without saving a language, the first option has focus when the screen opens, and the focus outline is the 2 px `text-primary` token, never colour alone.
- AC4 (tests and snapshots): a daemon test proves the transition: a successful language save records a hide/close of the old window and a new window build with the new language and `choose_language` false, and asserts that no keep-the-overlay path is taken; a failed save records no new build, the error state and `choose_language` true. A UI or welcome test drives the two selection outcomes and asserts `choose_language` false and no failure line on success, and `choose_language` true with the failure line on failure. `crates/ui/examples/welcome_snapshot.rs` gains `--choose-language`, and `crates/ui/tests/welcome_snapshots.sh` renders and compares four new references `welcome-choose-{en,ar}-{dark,light}.png` through the private headless KWin; without `--update` a missing reference fails and the candidate stays in the printed output folder for the Lead to approve, and `--update` writes the approved references. The snapshot does not run on a live desktop.
- AC5 (gates, dependency and changelog): `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, the tests of `kawaro-core`, `kawaro-ui` and `kawaro-daemon` and `scripts/design-lint.sh` pass in the touched scope; no new dependency; no em dash or en dash in any changed file. One `CHANGELOG.md` line in English and Arabic, placed under Unreleased, names S-130 and both the disappearing choice and the redesigned language screen.

## Out of scope
Changing the introduction page, the film, the settings pages or the app shell; a new window size or a new window; adding a third language; a language auto-detect screen (the current `Auto` resolution to the system language stays); the settings language list (it keeps its own S-117 behaviour); the `WelcomeWindow` settings embedded form; any change to tile or tray icons. The real-compositor focus and activation check is S-082 and is not claimed here.
